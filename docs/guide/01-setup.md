<a id="set-up-pstack"></a>

# pstack のセットアップ

このページでは、プラグインをインストールし、pstack が使用するモデルを選択して、最初のタスクを実行します。セットアップは 1 つのコマンドと短い会話だけです。

<a id="install-the-plugin"></a>

## プラグインをインストールする

Cursor チャットで、次を実行します。

```text
/add-plugin pstack
```

Cursorはプラグインがインストールされていることを確認します。

<a id="pick-your-models"></a>

## モデルを選択してください

実行:

```text
/setup-pstack
```

[`/setup-pstack`](../../skills/setup-pstack/SKILL.md) は、アクセス権のあるモデルを検出し、推論の予算を尋ね、各役割 (コードの委任、判断、レビューパネル) を示し、何が必要かを尋ねます。質問に答える。これは、すべての pstack スキルが読み取る小さなルールである `~/.cursor/rules/pstack-models.mdc` を書き込みます。

デフォルトは、`large` 予算と同じ、`xhigh` 推論で実行されます。 `unlimited` は、各モデルを最上位の階層 (最大 `max`) に引き上げます。Opusは `max` に移動します。 Grok は `xhigh` で最高となるため、そこに留まります。 `medium` と `small` は推論を低下させ、消費するトークンを減らします。

必要なものだけを上書きします。ルールに行のないロールは、スキルのデフォルトを維持します。デフォルトに戻すには、そのロールの行を削除します。 `/setup-pstack` を再実行すると、モデルがデフォルトと異なるロールはすべて保持されます。デフォルトが変更されると、変更前に作成されたルールによって古いデフォルトが固定されるため、これらのロール行を削除するか、ファイルを削除してから、`/setup-pstack` を再度実行します。

「自動」を使用するとどうなるか疑問に思われるかもしれません。ロールを `inherit-parent` または `auto` に設定すると、pstack はサブエージェント `model` フィールドを省略するため、サブエージェントは親チャット モデルを継承します。両方の値は同じことを意味し、どちらもモデルのスラッグではありません。パネル ロールの場合、値はリストであり、エントリごとに 1 つのサブエージェントが実行されるため、リストの長さによってパネル サイズが設定されます。セットアップでは、種族が各アームのモデルに名前を付けない限り、すべての `/swarm` ワーカーのデフォルト モデルである `swarm workers` も構成されます。

<a id="accept-the-verification-offer-or-dont"></a>

## 検証オファーを受け入れるか受け入れないか

セットアップの最後に、`/setup-pstack` は、プロジェクト内のアプリの動作を証明する方法 (`verify-*` スキルまたは既存のハーネスのいずれか) を探します。どちらも見つからない場合は、[`/create-verification-skill`](../../skills/create-verification-skill/SKILL.md) を使用して生成することを一度提案します。

「はい」と答えると、ユーザーと同じようにアプリを操作するようにエージェントに教えるプロジェクト ローカル スキルである `.cursor/skills/verify-<app>/` が書き込まれます。スキルを渡す前に一度スキルが機能することを証明します。 「いいえ」と答えて、セットアップを続行します。 `/create-verification-skill` はいつでも自分で実行できます。 [検証してリリース](./06-verify-and-ship.md#create-a-project-verification-skill) について詳しく説明します。

pstack を初めて使用する場合は、「はい」と答えてください。自身の作業をチェックできるエージェントは、チェックに合格するまで動作し続けます。エージェントはすべての結果を手渡してチェックすることができません。このガイドのすべての中で、検証スキルが最も役に立ちます。

セットアップ後、新しいチャットを開始します。モデル ルールは新しいセッションに適用されます。

<a id="keep-the-cost-in-check"></a>

## コストを抑える

pstack は、サブエージェントとレビュー パネルに追加のトークンを費やします。それが厳しさの代償だ。支出を減らすには:

- `/setup-pstack` を再実行し、推論予算が小さいか、より安価なモデルを選択してください。メインチャットの強力なモデルと、コードロールのより安価で高速なモデルを分けるのは適切です。
- ロールを `auto` または `inherit-parent` に設定して、チャット独自のモデルで実行されるようにします。
- パネルリストを短縮します。各エントリは 1 つのサブエージェントを実行します。
- 厳密さが必要な作業のために `/poteto-mode` を保存してください。小さくて明らかな編集はそうではありません。

<a id="run-your-first-task"></a>

## 最初のタスクを実行する

本物だが小さいものを選び、同僚に説明するような方法で説明してください。

```text
/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.
```

ToDo リストを見てください。最初の項目は、コピーされた一致したプレイブックのステップ、つまりこのプロンプトの機能プレイブックです。 `/poteto-mode` がステップをスキップした場合、そのステップは `skip: <reason>` とともにリストに残るため、何を実行しないことを選択したかがわかります。

ここから通常のフォローアップを入力できます。チャット全体で `/poteto-mode` をオンにしておくには、Enter の代わりに Option+Enter (Mac) または Alt+Enter (Windows) を使用して、`/` メニューから選択します。これにより、[カスタム モード](https://cursor.com/docs/skills) となり、終了するまで毎ターンコンテキスト内に留まります。カスタム モードは、エージェント ウィンドウと CLI で使用できます。 Plain Enter は 1 つのメッセージにスキルを付加し、チャットが進むにつれてフェードアウトします。

# 追加する前に削る

システムを進化させるときは、まず複雑さを取り除いてから構築します。

**理由:** 複雑なシステムに追加すると、さらに複雑になります。最初に削除すると、残されるコードが少なくなり、本質的な構造が明らかになり、通常は次の設計が明確になります。デフォルトは減算です。

簡素化を継続的な投資にします。デザインを少しシンプルにして、見つけたものと同じか、それよりも小さな表面の背後に残しておきます。

**パターン:**
- 構築前のシーケンスの削除
- 研磨する前にカットします (品質に投資する前に最小限に抑えます)
- 推測的なエッジケースではなく、観察された使用法を考慮した設計
- 仕様の要求を超える投機的なバリデーター、パーサー、またはガードはありません
- プロンプトを簡素化します (冗長な指示、過剰なテンプレートを削除します)。
- 参照に新規コンテンツがない場合は、スタブを残さずに削除します

# TypeScriptのベストプラクティス

最初に **type-system-discipline** 原則スキルを適用します。

| ルール | 概要 |
|------|---------|
| 判別可能なユニオン | `kind` のリテラル値でバリアントを区別し、不可能な状態を表現できなくします。任意フィールドの寄せ集めにしません。 |
| ブランドのタイプ | プリミティブには `& { readonly __brand: "X" }` を付けて、混同できないようにします。境界で一度検証します。 |
| 建設的なモデリング | 不正な値を構築できないように形状を構築します。空でない場合は `[T, ...T[]]`、偶数の長さの場合は `[T, T][]`、範囲の場合は `start` と `duration`。ランタイムガードではなく、改良型の希望でもありません。 |
| 全域性を保つ最も単純な型 | すべての操作が全域に定義できる間は `T[]` を維持します。緩い型のために `!`、キャスト、「起こらないはず」という例外が必要になる箇所だけ、`NonEmpty<T>` に強めます。 |
| `any` より `unknown` | 外部データは `unknown` として扱います。 |
| ガード前のスキーマ | プロパティごとの型ガードを手動で記述する前に、リポジトリのランタイム スキーマ ライブラリを使用し、`z.infer` などのスキーマから型を推測します。 |
| `as` キャストはありません |すべての `as` はランタイム クラッシュを待機しています。検証後にのみキャストします。 |
| 階層の絞り込み | 判別スイッチ > `in` 演算子 > `typeof`/`instanceof` > ユーザー定義型ガード > `as`。 |
| 型ガード | 主張を実際に検証する必要があります。誤った型ガードは、安全に見える名前の陰にバグを隠すため、`as` より危険です。`isX` または `hasX` という名前にします。 |
| 徹底 | デフォルトのアームでは `const _exhaustive: never = x;` をインライン化しているため、新しいバリアントが追加されるとコンパイラ エラーが発生します。 |
| `as` より `satisfies` | リテラル型を広げずに、値が型を満たすか確認します。 |
| 境界での検証 | 外部からデータが入る場所で、名前のあるドメイン型に解析します。`Record<string, unknown>` は、どんな別名でも、その解析箇所までにします。内部では型を信頼します。**boundary-discipline** の原則スキルを参照してください。 |
| スキーマ派生型 | 新しいインターフェイスを宣言する前に、`Pick`/`Omit`/`Parameters`/`ReturnType`/`Awaited`/`typeof` に到達します。 |
| オブジェクト引数 | 位置ではなくオブジェクトを渡すため、引数の順序は自動的に文書化されます。ホット パス (フレームごとのレンダリング、トークナイザー、パーサー) をスキップします。 |
| 実物を使うテスト | 実行できるものをモックにしません。リークやリソース解放をチェックできる、フレームワークの実際のテスト機能を優先し、実行中のビルドでUIを検証します。ローカルで動かせないものだけモックにします。 |
| 構造化テレメトリ | ID からデバッグするのに十分なコンテキストを備えた構造化ロガー診断を優先します。リリースされたコードに `console.log` がありません。 |

# ドメインをモデル化する

実ドメインを条件文に分散させるのではなく、データ構造内でエンコードします。

**理由:** 散乱したブール値、繰り返しの形状仮定、およびファイル全体に広がる分岐は、偶発的に複雑になります。ドメインに一致する構造は無効な状態を表現できなくなり、分岐が削除されます。書き込み時に選択すると安価です。後でそれを回復すると、リファクタリングとして読み取られ、延期されます。

**次のような構造に到達します:**

- 分散されたブール値、フェーズ、ライフサイクル チェックの代わりのステート マシン。
- 緩いパラメータや繰り返しの形状仮定ではなく、型指定されたオブジェクト/モデル。
- ファイル全体に広がる分岐の代わりに、マップ、レジストリ、ルックアップ テーブル、または判別ユニオン。
- アドホックな状態突然変異の代わりのリデューサーまたはコマンド/イベント モデル。
- ロード、検証、変換、保存などのシーケンスではなく、一連のドメイン知識を中心に編成されたモジュール。実行命令は所有権ではありません。
- 繰り返される動作、所有権、または不変条件を収集する小さなモジュール境界。
- データ アクセス パターンが必要とするキュー、キャッシュ、インデックス、グラフ/ツリー、または正規化されたコレクション。
- 適合するその他の構造。どれも適合しない場合は、コードで決して許可してはいけないものとデータの読み取り方法を検討し、それを正確にエンコードする構造を見つけます。

抽象化を強制しないでください。現在の形状がすでに明確で局所的であり、成長する可能性が低い場合は、退屈なコードを優先します。分岐、重複したルール、無効な状態、ライフサイクル リスクを削除せずに間接性を追加する抽象化には懐疑的になってください。

これをスキップした兆候は、既存の if/else チェーンをもう 1 つのブランチ、または最初のブール値と同期を保つ必要がある 2 番目のブール値によって拡張する新機能です。時間的分解も別の兆候です。フェーズ名付きモジュールは、ステップ全体で同じドメイン ルールを繰り返します。

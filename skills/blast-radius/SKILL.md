<a id="blast-radius"></a>

# 爆発半径

リリース前に、他の場所で壊れる変更を見つけます。 「爆発半径 X」、「これで何が壊れる可能性があるか」、またはまだ信頼できない小さな差分を確認するために使用します。

`how` および `why` のコンパニオン。 `how` は、コードの動作を示します。 `why` は、その形状になっている理由を示しています。爆発範囲は、他の場所で何が破壊されるかを示します。

発信者をリストするのは仕事ではありません。エージェントはこれらをすぐに grep できます。問題は、破損が grep で表示されないことです。

<a id="dont-trust-your-own-writeup"></a>

## 自分の書き込みを信用しないでください

正しく聞こえる爆破半径の書き込みには価値がありません。本当かどうかは別として、説得力があるように読めます。したがって、書き込みを返さないでください。全体が依存する 1 つまたは 2 つの事実を見つけて、コードを実行して証明します。

<a id="how-sure-are-you"></a>

### どれくらい確信していますか

変更の安全性が依存する各事実について、このリストの下の安いところまで取得し、どこで停止したかを述べます。

1. そう言いましたね。それ自体では価値がありません。
2. あなたはその行を指しました。実際の `file:line`、またはライブラリ独自のソース。
3. あなたは、悪いケースは起こり得ないことを示しました。失敗を一歩ずつ乗り越えたのに、届かない。
4. 実行しました。実際のコードを呼び出し、間違っていると大声で失敗するスクリプトまたはテスト。
5. 実行中のアプリで再現しました。

ステップ 4 は通常、アプリに同梱されているものと同じライブラリをインポートし、必要な関数を正確に呼び出す 1 つの小さなスクリプトです。

<a id="steps"></a>

## の手順

1. 変更を読み取ります。 diff、追加、変更、削除されるシンボル、および diff で説明されていない部分を含む、現在と異なる動作。 `why` ステップ 2 を使用して PR をプルし、コミットします。
2. 安全であるという事実を 1 つ見つけてください。危険に見える変更のほとんどは、「この呼び出しは既に無効になっているキャッシュ エントリを削除するだけで、他には何も行わない」という 1 つの事実により安全です。その事実を見つけてください。これが成立すれば、ほとんどの危険なケースは一度に解決されます。長いかもしれないリストに載せるのではなく、ここで時間を過ごしてください。
3. grep が停止する場所を見てください。呼び出すライブラリのソースを読み、その固定バージョンとローカル パッチを確認します。マイクロタスク、アンマウントとティアダウン、Solid と React など、物事が実行されるときに問題を解決します。シンボル検索で見逃されるものを追跡します。API が返す JSON、DB 列、ワイヤ形式、同じバイトを読み取る別の言語、機能フラグ、下流の 3 ホップのコードです。
4. それぞれのリスクについて正直になってください。それが実際に起こる可能性と、実際に起こった場合の実際のコストを想定してください。確認したリスクは守ってください。チェックしたものとクリアしたものを個別にリストします。 `why` と同じルール。実際の `file:line` を引用すると、何も見つからない検索でも答えが得られ、呼び出し元や API が作成されることはありません。
5. 1 つの事実を証明してください。実際のコードを実行するスクリプトまたはテストを作成し、実行して、何が起こったかを貼り付けます。
6. 大きな変更または大幅な変更の場合は、`arena` として実行します。複数のモデルに同じ質問をし、答えを結合します。モデルが異なれば、実際のバグも異なります。

<a id="what-to-hand-back"></a>

## 何を返すか

- **内容。** 明らかではない部分も含めて、何が変更されました。
- **これが安全であるという 1 つの事実。** それを述べ、どの段階に到達したかを述べ、その証拠を示してください。証明できなかった場合は証明されていないと書きましょう。
- **リスク。** それぞれ、破損の仕組み、`file:line`、可能性と危険度、および確認方法を示します。重要なものについては証拠を貼り付けます。
- **クリアしました。** チェックした内容と、問題ない理由。
- **マージする前に** 作成したスクリプトを含む、実際のバグを捕捉する最も安価なテストまたは再現。

`unslop` を通じて記述し、実際のコードを引用し、公開される前にプライベートなものをすべて取り除きます。

**返信:** 上記の記事には、安全性に関する事実が 1 つ証明されているか、証明されていないとマークされています。

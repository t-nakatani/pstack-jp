# 根本原因を直す

デバッグ中は、症状を修正しないでください。すべての問題を根本原因まで追跡し、そこで修正します。

**理由:** 症状の修正は蓄積されます。それぞれの回避策により、システムの推論が困難になり、実際のバグは残ります。根本原因の修正は最初は時間がかかりますが、合計のデバッグ時間は短縮されます。

**パターン:**
- 最初に複製します
- 根本原因が見つかるまで「なぜ」を尋ねる
- ガードを追加しないでください (クラッシュを黙らせるための nil チェックの追加は症状の修正です)
- 回避策を正当化するために段落にわたるコメントが必要な場合、コードが間違っています (コメントではなくコードを修正してください)
- インスタンスだけでなくパターンをチェックします (同じパターンを grep し、すべてのインスタンスを修正します)
- 詰まった場合は、計器。推測しないでください (ログを追加し、実際のエラーを読み取ります)

**再起動のバグ: コードの前に疑わしい状態**

何かが「再起動後に失敗する」場合は、まず古い永続状態 (構成ファイル、キャッシュ、ロック ファイル、シリアル化された状態) を疑います。状態ファイルをクリアすると動作が復元される場合は、修正として状態の検証を優先してください。

# 実装ではなく振る舞いをテストする

テストは、ユーザーが行う方法でコードを呼び出し、観察した結果をリテラルの期待値に対してアサートします。作成されたコードの呼び出しをアサートするテストや、コードに含まれる定数を再ステートするテストは、どちらも行いません。

チェック: テストを続ける前に、インポートするすべての関数が `undefined` を返した場合でも合格するかどうかを尋ねます。 「はい」の場合、動作は観察されず、欠陥によって失敗することはありません。アサーションを書き直すか、テストを削除してください。

**理由:** 欠陥のために失敗できないテストでは、CI 時間とレビューの注意がかかり、何も捕捉できません。定数ピンは、誰かが定数または定数が再表現するプロンプトを編集したときにも失敗するため、その編集が妨げられます。

**インポートされたすべての関数が `undefined` を返した場合でも通過する 5 つの図形:**

- **アサーションが弱い、またはアサーションがありません。** `expect` がないか、`toBeDefined`、`toBeTruthy`、`not.toThrow`、`toBeInstanceOf`、`toBeGreaterThan(0)` のみ。
- **モックまたは欠席のみ。** `toHaveBeenCalled`、`not.toHaveBeenCalled`、`toBeUndefined`、`toEqual([])`、`toHaveLength(0)`、`not.toBe(wrongValue)` のみ。
- **自己参照。** 期待値はテスト対象のコードから取得されます: `expect(f(a)).toBe(f(a))`、`expect(parsed.url).toBe(buildUrl(...))`。
- **定数ピン。** アサーションは、手作業で管理された定数、設定のデフォルト、テーブル行、またはプロンプト文字列を再表現します: `expect(LIMITS.maxTools).toBe(8)`、`expect(PROMPT).toContain("You are")`。
- **フィクスチャはフィクスチャをアサートします。** アサーションは、テストが構築したデータまたは `beforeEach` で計算された値を読み取り、サブジェクトが本体内で実行されることはありません。

**修正:** 1 つの具体的な入力を使用してテスト本体内のサブジェクトを呼び出し、リテラル出力または観察可能な効果 `expect(slugify("Hello, World!")).toBe("hello-world")` をアサートします。不在の場合は、同じテストで他の入力で存在をアサートします。定数の場合は、値を再記述するのではなく、1 つの入力で定数を読み取るメカニズムをテストします。モックの場合は、呼び出されたということではなく、受信したペイロードまたは呼び出し後の状態をアサートします。そのようなアサーションが存在しない場合は、テストを削除します。

テーブルの行間のリレーション (2 つのテーブルに存在するキー、存在する親) のテストとコンパイル時のチェックを `*.test-d.ts` ファイルに **保持** します。

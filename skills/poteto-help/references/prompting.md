<a id="word-the-prompt"></a>

# プロンプトを言葉で入力してください

プロンプトには、意図と完了のチェックが示されます。プレイブックには手順が記載されているため、いくつかの平易な文で仕様を上回ることができます。

<a id="put-in"></a>

## 入れてください

- ゴールです。何が問題なのか、ユーザーが何を望んでいるのかを伝えます。
- チェックが完了しました。合格することも失敗することもあります。 「より良くする」と期間はチェックではありません。
- 示すべき証拠。実際のコマンド出力、フローのビデオ、保存された値、または前後の数値を尋ねます。
- ユーザーがすでに知っていること。症状、再現手順、ログ、またはリンクにより、エージェントは検索を節約できます。
- 実際の制約。 「最初に再現する」、「まだコードを変更しない」、「動作変更なし」、および「続行する前に確認させてください」は、それぞれエージェントの動作を変更します。

<a id="leave-out"></a>

## 省略します

- その方法。何を達成するかを伝え、より良い方法を見つけるためにエージェントの部屋を出ます。
- スキルまたはステップのリスト。手書きの命令により、プレイブックに保持されているステップが削除または並べ替えられます。スキルに名前を付けるのは、1 つの選択肢を上書きする場合のみです。
- エージェントが問題を再度説明するまでの、原因に関するユーザーの理論。推測を明示すると、検索が絞り込まれます。

<a id="load-the-context-first"></a>

## 最初にコンテキストをロードします

- ノイズの多いレポートの場合は、何かを行う前に、根本的な問題を自分の言葉で平易な英語で言い直すようエージェントに依頼してください。読み間違いは、コードが存在する前に現れます。
- 新しいチャットで、`/recall` さんが以前にこのトピックに取り組んでいます。古いチャットには、新しいエージェントにはないコンテキストが保持されています。
- 見慣れないコードに変更を加える前に、仕組みについては `/how` に、理由については `/why` に尋ねてください。トレースされたモデルを持たないエージェントは、最初に考えられる箇所で症状を修正します。
- `/teach` に、「症状ではなく原因が解決することを納得してください」のように、選択の根拠を示すように依頼します。ケースは概要よりも確認しやすいです。

<a id="design-before-the-plan"></a>

## 計画前のデザイン

- 最初のデザインは決して採用しないでください。 UI のスクリーンショットまたはビデオを含むいくつかのオプションのプロトタイプを要求し、証拠から選択します。
- プロトタイプに未解決の質問に答えてもらいましょう。抽象的な計画を敵対的にレビューしないでください。レビュー担当者は決して起こらないリスクをでっち上げるからです。
- 共有パッケージまたは API については、まず README またはチュートリアルを求めてから、コードに戻ります。ドキュメントは、エージェントが自身をチェックするターゲットになります。
- プランのご依頼はデザインが決まってからお願いします。計画の各ステップはチェックで終了します。

<a id="follow-up-short"></a>

## 短いフォローアップ

- 「実行してください」、「続行してください」、「完了するまで続けてください」は、チャットがタスクを保留すると、完全なプロンプトになります。
- 件名が変わったら「新しいタスク」から始めます。それ以外の場合、モードはメッセージを次のステップとして処理します。

<a id="before-stepping-away"></a>

## 立ち去る前に

- 「寝るつもりです」または「ちょっと離れます」と言って、エージェントが尋ねるのをやめます。
- 反復ごとに実行できるチェックとして書き込みが完了し、その述語を `/loop` に与えます。
- 名前付きベースから新しいワークツリーを要求します。
- 「コミットする前に質問しないでください」など、エージェントが何のために停止するのかを事前に回答します。
- 後で監査するための決定ログを要求します。
- 「数時間経っても本当に行き詰まったら、立ち止まって理由を書いてください」と出口を与えます。

<a id="steer-in-one-line"></a>

## 一列にステアリングします

- 目標をもう一度言います: 「目標は再現することだと言いました。まだ修正は求めていません。」
- 原則に「適用して機能することを証明してください。ビルド ログではなく、実際の出力を見せてください。」という名前を付けます。
- エージェントがすでにルールを読んでいるため、プリンシパル名は機能します。その返信には、ルールが変更した決定の名前が記載されています。

# ぽてとヘルプ

pstack に関するユーザーの質問に答え、送信できるプロンプトを渡し、答えの元になったファイルをリンクします。ヘルプの質問については、作業を開始しないでください。ユーザーがその方法を尋ねたところ、pstack の実行には実際のトークンが消費されるため、プロンプトを送信させます。

「pstack を使用してこのバグを修正してください」などの作業を求めるメッセージは、ヘルプの質問ではありません。 [`poteto-mode`](../poteto-mode/SKILL.md) を読み、その下で作業を実行し、カスタム モードがオンのままであることを一度言及します。

このファイルは、質問をスキルと答えを含むガイド ページにマップします。これらのファイルは詳細を所有します。引用する前にルーティング先のファイルを読み、このマップと一致しない場合はそれを信頼してください。ここのリンクは、インストールされているプラグインを指していますが、ユーザーは開くことができない場合があるため、ファイルのパブリック コピーである `https://github.com/cursor/plugins/blob/main/pstack/` の後にそのパスを指定してください。

<a id="find-out-what-they-need"></a>

## 何が必要かを調べる

メッセージと会話からニーズを推測します。 「どのスキルが PR をレビューしますか?」などの名前付きの状況は、そのセクションに直接進みます。必要性がまだ不明瞭な場合は、次のオプションを使用して多肢選択式の質問を 1 つ質問し、選択されたセクションのみに答えてください。

- セットアップする
- `/poteto-mode` でタスクを開始します
- 状況に応じたスキルを選択してください
- 間違った実行を修正する
- pstack を自分のものにする

答えを変更する状態を確認し、変更された場合にのみ言及します。

- いいえ `~/.cursor/rules/pstack-models.mdc` は、`/setup-pstack` がこのユーザーに対して実行されていないことを意味するため、すべてのロールはデフォルト モデルを使用します。
- プロジェクトに `verify-*` スキルや他のアプリ ハーネスがないということは、エージェントがアプリを操作するためのスクリプト化された方法がないことを意味します。質問が変更が機能することの証明に関するものである場合は、`/create-verification-skill` と言及してください。

モデル ルールが欠落していてそれが重要な場合は、各役割と推論予算に応じてモデルを今すぐ選択するかどうかをユーザーに尋ねます。ユーザーが初めての場合が重要であり、問題はセットアップやコストに関するものであり、その答えはどのモデルが実行されるかによって異なります。チャットごとに最大 1 回質問してください。必要性も不明瞭な場合は、両方の質問を一緒に質問してください。 2 つの選択肢を提供します。

- 次に、`/setup-pstack` と入力して質問に答えてください。
- その後: 質問に答え、`/setup-pstack` を実行するまですべてのロールがデフォルト モデルを維持するという 1 行を追加します。

<a id="get-set-up"></a>

## セットアップする

1. チャットで `/add-plugin pstack` を使用するか、サイドバーの [カスタマイズ] からインストールします。
2. [`/setup-pstack`](../setup-pstack/SKILL.md) を実行します。推論の予算を要求し、モデルを各役割にマッピングし、ルールを作成します。このルールは新しいチャットに適用されます。
3. `/poteto-mode`、目標、および合格または不合格のチェックを使用して実際のタスクを開始します。

インストールしても、ユーザーがスキルを呼び出すまでは何も変わりません。ユーザーの言葉からは `/setup-pstack` のみがロードされます。 [README](../../README.md) および [ガイド ページ 1](../../docs/guide/01-setup.md) に詳細が記載されています。 [`references/prompting.md`](references/prompting.md) に従って、最初のプロンプトを伝えるように申し出ます。

コストが心配な場合は、トークンの行き先と支出を減らす方法を考えてください。 pstack は、サブエージェントとレビュー パネルに追加のトークンを費やします。 `/setup-pstack` を再実行し、より少ない予算または安価なモデルを選択してください。 `auto` または `inherit-parent` に設定されたロールはチャットのモデルで実行され、チャットが Auto またはより安価なモデルで実行されるとトークンが節約されます。パネル リストが短いほど、実行されるサブエージェントの数が減り、エントリごとに 1 つずつ実行されます。厳密さが必要な作業のために `/poteto-mode` を保存してください。

pstack は Cursor 用に構築されています。そのスキルはエージェント スキル形式を使用しているため、他のツールで読み取ることができます。ただし、`/poteto-mode`、`/how`、`/why`、`/teach` などのほとんどのワークフロー スキルは、ロールごとのモデルを使用して Cursor サブエージェントを生成し、カスタム モードと `/loop` は Cursor 機能であるため、これらの部分は機能しない可能性があります。

<a id="start-a-task-with-poteto-mode"></a>

## `/poteto-mode` でタスクを開始します

`/poteto-mode` は、タスクをプレイブックに照合し、プレイブックのステップを ToDo リストにコピーし、ステップで必要な他のスキルを実行します。スキップしたステップはリストに `skip: <reason>` として残ります。適切なプロンプトには、目標とそれが完了したことを伝える方法が記載されています。手書きのシーケンスでは、プレイブックに保持されるステップが省略されたり、順序が変更されたりする傾向があるため、スキルはリストされていません。単語 1 つを手伝う前に、[`references/prompting.md`](references/prompting.md) をお読みください。 [ガイド ページ 2](../../docs/guide/02-poteto-mode.md) には例があります。

`/poteto-mode` がオンのままかどうかは、ユーザーの起動方法によって異なります。

- `/poteto-mode` に入力すると、スキルが 1 つのメッセージに添付されます。チャットが進むにつれて消えていきます。
- Mac では Option+Enter、Windows では Alt+Enter、またはスキル エントリからモードとして使用すると、カスタム モードになります。ユーザーがモードを終了するまで毎ターンコンテキスト内に留まり、カジュアル ターンには含まれません。
- Cursorのドキュメントには、エージェント ウィンドウと CLI のカスタム モードがリストされています。他の場所では、`/poteto-mode` で新しいタスクを開始します。 これが表示されたら、

[Cursorのスキル ドキュメント](https://cursor.com/docs/skills) をリンクします。チャット中に「新しいタスク」を実行すると、モードが新しいプレイブックと一致します。 `/poteto-mode` は、プレイブック ステップが生成するサブエージェントにすでに `poteto-agent` を使用しています。自分のサブエージェントから同じスタイルを取得するには、`subagent_type: "poteto-agent"` を使用してサブエージェントを生成します。

<a id="pick-a-skill"></a>

## スキルを選択してください

デフォルトの答えは `/poteto-mode` で、ステップで必要な場合に他のほとんどが実行されます。ユーザーがプレイブックで提供されているものより多かれ少なかれ何かを望む場合は、スキルに直接名前を付けます。スキルを推奨する前にスキルを読み、プロンプトの例を 1 つ挙げてください。

| ユーザーは次のことを望んでいます | スキル |
|---|---|
| 重要なタスクはすべて厳密に実行します | [`/poteto-mode`](../poteto-mode/SKILL.md) |
| コードが現在どのように動作するか、または新しいコードがどこに存在すべきかを知る | [`/how`](../how/SKILL.md) |
| コードがなぜこのような形状になっているのか、または数値がどこから来たのかを知る | [`/why`](../why/SKILL.md) |
| 変更やサブシステムをわかりやすく説明 | [`/teach`](../teach/SKILL.md) |
| あるトピックに関する自分の最近の取り組みを確認する | [`/recall`](../recall/SKILL.md) |
| 小さな差分がそれ自体の外側で何を破壊する可能性があるかを知っています | [`/blast-radius`](../blast-radius/SKILL.md) |
| コードが関数境界を越える前に型とモジュールの形状を解決します | [`/architect`](../architect/SKILL.md) |
| 1 つのブリーフで複数の試行を取得し、最良のものに統合します | [`/arena`](../arena/SKILL.md) |
| クラウド エージェントとしてスライスまたは競合ワーカーに対して並列チェックを実行します | [`/swarm`](../swarm/SKILL.md) |
| さまざまなモデルに差分を確認させ、それを破ってみます | [`/interrogate`](../interrogate/SKILL.md) |
| 安価なローカル テストが存在する場合は、バグ テストを修正します。 | [`/tdd`](../tdd/SKILL.md) |
| TypeScript ルールを `.ts` または `.tsx` の作業に適用する | [`/typescript-best-practices`](../typescript-best-practices/SKILL.md) |
| コメントを書いていないレビュー担当者を使用して、レビュー前にコメントを削除します | [`/no-comments`](../no-comments/SKILL.md) |
| クリーン AI が文章で語る | [`/unslop`](../unslop/SKILL.md) |
| ドキュメント、RFC、README、PR の説明、またはコミット メッセージを標準に書き込む | [`/technical-writing`](../technical-writing/SKILL.md) |
| 最後の返答をわかりやすい言葉でもう一度聞きます | [`/bro`](../bro/SKILL.md) |
| エージェントにアプリを操作して動作を証明するためのスクリプト化された方法を提供する | [`/create-verification-skill`](../create-verification-skill/SKILL.md) |
| 検証スキルとその機能マップをアプリと連携させます | [`/maintain-verification-skill`](../maintain-verification-skill/SKILL.md) |
| パフォーマンス数値を報告したり、それに基づいて行動したりする前に精査してください | [`/benchmark-checklist`](../benchmark-checklist/SKILL.md) |
| 大規模な変更または横断的な変更を実行するか、撤退後にレビューする変更を実行する | [`/figure-it-out`](../figure-it-out/SKILL.md) |
| 実行中に意思決定ログを記録し、後で確認します。 | [`/show-me-your-work`](../show-me-your-work/SKILL.md) |
| 各役割と推論予算に応じたモデルを選択します | [`/setup-pstack`](../setup-pstack/SKILL.md) |
| 自分の仕事習慣を個人モードのスキルに変える | [`/automate-me`](../automate-me/SKILL.md) |
| 完了したタスクの教えをスキル編集に変える | [`/reflect`](../reflect/SKILL.md) |
| エージェントがこのリポジトリで同じ間違いを繰り返さないようにする | [`/correct`](../correct/SKILL.md) |
| Webhook 経由で Grok Bot を起動するボタンを備えたページを構築する | [`/make-bot-ui`](../make-bot-ui/SKILL.md) |
| pstack を回避する方法を見つける | `/poteto-help` |

このディレクトリの隣にあるスキル ディレクトリがテーブルにない場合は、その前付を読み、その説明に従ってルートを確認します。 `principle-*` ディレクトリは、以下の原則に基づいて説明されています。

危機一髪:

- `/how` はコードの動作を説明しています。 `/why` でその理由が説明されています。 `/teach` は一方または両方を実行し、結果をわかりやすく説明します。
- `/arena` は、すべての作業者に同じ概要を提供し、最良の部分をマージします。 `/swarm` は作業をスライスまたはレースに分割し、1 つのレポートを返します。
- `/architect` は、デザインを確定した直後に実装されます。コードを記述する前に設計をレビューするには、「チェックポイント付き」を追加します。
- `/interrogate` が差分をレビューします。 `/blast-radius` は、diff の外側の破損を探し、変更を安全にする 1 つの事実を証明します。
- `/recall` は、最近のチャット全体のコンテキストを再構築します。特定のチャットまたはブランチを再開するのが、セッション ピックアップ プレイブックです。
- `/figure-it-out` は 1 つの厳密な実行を設計します。 Orchestrate プレイブックは、数日間にわたるプログラムと多くの PR を実行します。 Autonomous run プレイブック は、1 つのタスクを終了条件まで駆動します。

pstack にありません:

- `/deslop`、`control-cli`、および `control-ui` は `cursor-team-kit` プラグインに同梱されています。
- `/loop` および `/create-skill` はCursorの組み込みです。
- pstack には `/orchestrate` スキルがありません。 Orchestrate は `/poteto-mode` プレイブックです。スラッシュ メニューに `/orchestrate` が表示されている場合は、別のプラグインがそれを提供します。

<a id="playbooks-and-principles"></a>

## ハンドブックと原則

プレイブックはスキルではなく、`/poteto-mode` 内のステップ リストであるため、スラッシュ コマンドはありません。 `/poteto-mode` 内でタスクを説明することで 1 つが選択され、次のフレーズで 1 つを直接指定します。

- 「この pr をベビーシット」または「pr 123 をチェック」はベビーシットを実行します。これにより PR がマージ準備完了状態になり、そこで停止します。ユーザーが合流、着陸、またはリリースを要求しない限り、合流しません。
- 「スタックを着陸」は配送を実行します。
- 「このブランチを引き継ぐ」はセッション ピックアップを実行します。
- 「安全に一時停止」は安全に一時停止を実行します。
- 「このキューの完全な自動操縦」は、自動操縦を完全に実行します。 「積み上げてリリースしない」は Autopilot-stack を実行します。
- 「eval プレイブックを実行」は Eval を実行します。

`/poteto-mode` がないと、「この pr のベビーシット」などのフレーズで、代わりに同じジョブのCursor自身のスキルを開始できます。 [`poteto-mode`](../poteto-mode/SKILL.md) の プレイブックs セクションには、すべての プレイブック とそれがいつ適用されるかがリストされています。 [ガイド ページ 6](../../docs/guide/06-verify-and-ship.md) では、PR のオープン、ベビーシッター、およびランディングについて説明します。

pstack には計画スキルがありません。Cursorのプラン モードはそれと並行して動作します。複数のフェーズまたはスタックされた PR にまたがる作業の場合、`/poteto-mode` に計画を要求すると、[複数フェーズ計画プレイブック](../poteto-mode/playbooks/multi-phase-plan.md) が実行されます。これは計画を作成しますが、実装はしません。設計に関する質問については、プロトタイプ プレイブックまたは `/architect` が最初にコードで解決します。

原則は、`/poteto-mode` が読んで返信で引用する 1 つのルールのスキルです。ユーザーがこれを呼び出すことはほとんどありません。 「適用して機能することを証明してください。実際の出力を見せてください。」のように、代わりに名前を使用して操作します。 `/principle-<name>` と入力しても、オンデマンドで 1 つロードされます。 [ガイド 8 ページ](../../docs/guide/08-principles.md) にリストされています。

<a id="fix-a-run-that-went-wrong"></a>

## 間違った実行を修正する

| 症状 | 修正 |
|---|---|
| 数ターン後にモードの適用が停止しました | Enterで起動されました。カスタム モードとして開始するか、`/poteto-mode` で各タスクを開始します。 |
| 質問が最後のタスクの次のステップとして扱われました | 「新しいタスク」と言うか、そのターンにはそのモードは必要ないと言ってください。 |
| 新しいモデルを選択しても効果がありませんでした | `/setup-pstack` のルールは新しいチャットに適用されます。一つ始めてください。 |
| 予想よりも実行コストがかかる | 「セットアップ」のコストに関する段落を参照してください。 |
| スキルが単独でロードされませんでした | ユーザーの言葉からは `/setup-pstack` のみがロードされます。他のものは、ユーザーが入力したとき、または `/poteto-mode` が実行したときにロードされ、すべてのスキルが実行されるわけではありません。 |
| 並列エージェントが相互に上書きしました | 各エージェントに独自のワークツリーを与えるか、それぞれが独自のマシンを取得するクラウド エージェントとして実行します。 |
| 夜間の実行は移動しましたが、何も完了しませんでした | `/loop` には、期間ではなく、成功または失敗するチェックが必要です。 [ガイド 7 ページ](../../docs/guide/07-overnight.md) を参照してください。 |
| 返信では、グリーン ビルドが成功したことが主張されています | 実際のコマンド、フロー、保存された値、またはプロファイルを要求します。それが実証性の原則です。 |

ドリフト走行の場合、[`references/prompting.md`](references/prompting.md) には 1 ラインのステアがあります。 [ガイド 10 ページ](../../docs/guide/10-recipes-and-pitfalls.md) にはさらに落とし穴があり、コピーする価値のあるレシピが含まれています。

<a id="make-pstack-my-own"></a>

## pstack を自分のものにする

- [`/automate-me`](../automate-me/SKILL.md) は、`/poteto-mode` と一緒に使用するために、ユーザー自身の履歴から個人モードのスキルを作成します。
- [`/reflect`](../reflect/SKILL.md) セッションがレッスンをユーザーが承認したスキル編集に変換した後。
- `/poteto-mode write a skill for <workflow>` はオーサリング プレイブックを実行します。 eval プレイブックはスキル変更をブラインドでテストします。
- 誤動作した機能作業内ではなく、スキル自体の PR 内で誤動作を修正します。

[ガイド 9 ページ](../../docs/guide/09-make-it-yours.md) では、これらのそれぞれについて説明します。

<a id="reply"></a>

## 返信

答えを導きましょう。コード ブロック内でプロンプトの例を 1 つだけ指定し、適合する場合は [`references/recipes.md`](references/recipes.md) から適合させてから、そのファイルへのリンクを指定します。ユーザーがマップ全体を要求しない限り、短くしてください。

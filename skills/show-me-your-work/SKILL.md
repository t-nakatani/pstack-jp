<a id="show-me-your-work"></a>

# あなたの作品を見せてください

正規ログを 1 つ保持します。

<a id="the-format"></a>

## フォーマット

単一の TSV ファイル、決定ごとに 1 行。セルは単線のままです。証拠は指針であり、文章ではありません。

`references/decision-log-template.tsv` (ヘッダー行) をコピーして、クリーンなログを開始します。列:

- **ts.** ISO8601 タイムスタンプ。
- **フェーズ。** フェーズまたはワークストリーム。
- **決断。** 選択したこと、行ったことを 1 行にまとめます。
- **なぜ。** 理由を分かりやすく説明します。原則に基づいている場合は、専門用語のタグではなく、はっきりと述べてください。
- **証拠。** それを証明するリンクまたはパス: コミット SHA、PR 番号、`file:line`、またはアーティファクト、トレース、またはスクリーンショットのパス。決して段落ではありません。
- **結果。** 結果または述語の状態: `tests green`、`reverted`、`pixel-diff 0`、`INCONCLUSIVE`、`open`。

例は、レビュー担当者が一目で読めるように平易に話されています。

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	counted the work first, about 100 components and roughly 75 hours	wanted to know the size before starting a long run	commit 3a9f1c2	found 5 things to sort out before starting
2026-05-24T09:40:00Z	harness	took screenshots of the old version before changing anything	so we can compare old against new and catch any visual change	scripts/snapshot.sh, baseline/	saved 120 reference screenshots
2026-05-24T11:15:00Z	widget	moved the widget styles over without changing how it looks	keep the change small and the result identical	commit 7c21e0a, pixel-diff 0	looks identical, tests pass
2026-05-24T12:30:00Z	widget	threw out a helper's work because its screenshots were blank	checked the real files instead of trusting its summary	worktree reset	reverted, tightened the instructions for next time
```

<a id="logging-a-row"></a>

## 行のログを記録しています

各エントリは、自分が何をしたかをチームメイトに伝える方法で書きます。平易な言葉、具体的な行動、AI が話すことや抽象的な専門用語はありません (**unslop** スキルはログ テキストにも適用されます)。

ヘルパー `scripts/log.sh <logfile> <phase> <decision> <why> <evidence> <result>` を使用します。 `ts` をスタンプし、最初の使用時にヘッダーを書き込み、不要なタブ/改行を削除し、`=`、`+`、`-`、または `@` で始まるセルの前に一重引用符を付けます。行を追加する単純な `printf` も機能しますが、セルが生成されたテキストまたはユーザーが指定したテキストからのものである場合は、同じバイトに注意してください。

すべてのアクションではなく、意思決定ポイントとチェックポイントをログに記録します。選択されたフォーク、検証結果で完了したユニット、トリガーによるピボットまたはリバート、ブロッカーの浮上、ゲートの固定。ループ実行の場合、反復ごとに 1 行。些細で自明のことは飛ばしてください。

実行とは、その後のターンとその要約を含む 1 つのエージェントの会話です。ピックアップ、代替エージェント、または新しいチャットにより、新しい実行が開始されます。すでに行があるログに実行を追加すると、その最初の行にはフェーズ `start` が含まれ、別の実行の `start` 行の後の最初の行も同様になります。したがって、後のターンでログに戻る実行では、最初にログの最後の行を読み取り、それ以降に別の実行が書き込んでいるかどうかを確認します。 `start` 行は、この実行が書き込まなかったその前の行の `ts` 範囲に名前を付けます。また、エージェント ID など、その証拠によってこの実行に名前が付けられます。フェーズ `start` は他には何も使用しません。

<a id="where-it-lives"></a>

## それが住んでいる場所

デフォルトでは、ログは作業成果物であり、コミットされていません。これを作業ディレクトリの `decisions.tsv` に保持するか、複数の作業を同時に実行する場合は `.audit/<task-slug>.tsv` に保持し、git の外に残しておきます。

作業が野心的で、レビュー担当者が結果を信頼するための証跡が必要な場合にのみコミットしてください。

<a id="rules"></a>

## ルール

- 追加のみ。間違った呼び出しは、それを置き換える新しい行を取得します。履歴を編集または削除しないでください。
- 手作りの 1 回限りの証拠 (**encode-lessons-in-structure** 原則スキル) よりも、コミットされたスクリプトによって生成された証拠を優先します。

<a id="audit-the-log-against-the-transcript"></a>

## トランスクリプトと照らし合わせてログを監査する

実行の最後に、返す前に、ログが真実を示していることを確認してください。アクティブなワークスペースの `agent-transcripts/` ディレクトリにあるこの実行のトランスクリプトを読み取ります (システム プロンプトによってパスが指定されます)。 `~/.cursor/projects/*/` を越えてグロブしないでください。無関係なプライベートチャットが読み取られます。実際に起こったことと照らし合わせて、このランの列を歩きます。それらの各ストレッチは、この実行の `start` 行の 1 つ、またはこの実行でログが作成された場合は最初の行から始まり、別の実行の次の `start` 行で終了します。

- すべての行が実際の決定またはアクションにマッピングされていることを確認します。
- 各行の証拠が解決され、行の主張が示されていることを確認します。
- フォーク、ピボット、または放棄されたアプローチによって作業が形成されたものの、ログに記録されていないものはギャップです。追加してください。

ストーリーではなくログを修正してください。監査では、作成された行であっても、行を編集または削除することはありません。行に実際の決定も実際の行動も記録されていない場合、またはその主張や証拠が間違っている場合は、実際に起こったことで置き換える行と、解決するポインターを追加します。この監査では、この実行範囲外の行はチェックされません。この実行自体の結果でそれらの 1 つが間違っていることが示された場合は、他の間違った呼び出しと同様に、それを置き換えます。

<a id="cross-model-review-of-the-trail"></a>

## トレイルのクロスモデルレビュー

ハンドバックする前に、作業を行ったモデル ファミリとは異なるモデル ファミリでサブエージェントを生成します。自己レビューは代わりにはなりません。サブエージェントは監査証跡と実行のトランスクリプトを読み取り、ユーザーが注意すべき点にフラグを立てます。作業をやり直すのではなく、最適ではないものや危険なものをスキャンします。

- 証拠が弱い、または証拠がないまま記録された決定。
- 検証手順がスキップされたか、記録に証拠がないと主張されました。
- 後から考えると危険に見える選択 (時期尚早、範囲が忍び寄る、症状の上塗り)。
- カジュアルな流し読みではユーザーが見逃してしまうギャップ。

トレイルを生成した実行に対するすべての応答は、「注意」セクションで終わります。レビュー担当者のモデルを独自の行 (`reviewed by <model>`) で先頭に置き、次に特定の行または瞬間を指す各フラグをリストします。 「フラグなし」が有効な値です。モデル名は違います。

<a id="reviewing-the-trail"></a>

## トレイルを確認する

上から下まで読んで、証拠の指示に従って、スポットチェックしてください。 GitHub は、コミットされた TSV をテーブルとしてレンダリングします。 `column -s$'\t' -t decisions.tsv` は端末にレンダリングします。

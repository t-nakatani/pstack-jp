# 設計の選択肢を探り尽くす

新しいインタラクションまたはアーキテクチャ上の決定に確立された前例がない場合は、実装前にいくつかの具体的な代替案を検討します。間違ったものを構築することは、3 つの選択肢を検討するよりもコストがかかります。

**ルール。** 正しい答えが明らかでない場合は、競合するプロトタイプまたはスケッチを 2 ～ 3 つ作成します。並べて比較してください。その後にのみコミットします。 「二度設計する」とは別名このルールです。最初の形状の 2 番目のフレーバーはカウントされません。

**適用される場合:**
- 斬新な UI インタラクション (コードベースに先行技術なし)
- 複数の実行可能なアプローチによるアーキテクチャの選択
- ユーザー エクスペリエンスがロジックではなく感触に依存する製品設計の決定

**そうでない場合:**
- パターンが確立される機械的実装
- バグ修正または明確なターゲット状態でのリファクタリング
- 制約により単一の実行可能なアプローチが決定される変更

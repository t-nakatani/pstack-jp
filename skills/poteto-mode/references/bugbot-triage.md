# バグボットのトリアージ

Babysit プレイブック (`../playbooks/babysit.md`) がバグボットまたはレビュー自動化コメントを処理する場合は、このリファレンスを使用します。目標は、デフォルトで Bugbot を無視することではありません。目標は、すべてのコメントを必要なコード変更として扱うのをやめることです。

<a id="decision-rubric"></a>

## 決定ルーブリック

行動する前に、各 Bugbot スレッドを分類します。

- `fix`: コメントは、正当性、セキュリティ、プライバシー、データ損失、認証、請求、移行、冪等性、競合、またはリリース時の動作の問題を特定します。最下位の所有 PR で修正し、コミット SHA で応答してスレッドを解決します。
- `dismiss`: コメントは文書化された低リスクのノイズの多いパターンと一致しており、現在のコード/コンテキストは、懸念事項にコード変更が必要ないことを証明しています。短い理由を返信してスレッドを解決します。
- `ask`: コメントは新規、重大度が高い、セキュリティ/プライバシー/データ関連、または曖昧です。推測するのではなく、ユーザーに尋ねてください。

疑問がある場合は、質問してください。騒がしいコード品質のコメントをスキップするのは安上がりです。実際のデータやセキュリティ バグをスキップすることはできません。

<a id="learned-pattern-format"></a>

## 学習パターン形式

この形に将来のパターンを追加します。

```markdown
### <short pattern name>

- Confidence: candidate | recurring | strong
- Skip when: <conditions that must be true>
- Do not skip when: <risk boundaries>
- Example signal: <phrases or code context that identify the pattern>
- Source: <PR/comment URL or short historical note>
```

1 つまたは 2 つの例として `candidate` を使用します。実際に複数回解雇された場合は、`recurring` を使用してください。 `strong` は、パターンが狭く、繰り返し検証され、リスクが低い場合にのみ使用してください。

<a id="recurring-skip-candidates"></a>

## 繰り返しスキップ候補

<a id="intentional-ui-or-design-system-visual-changes"></a>

### 意図的な UI またはデザイン システムの視覚的な変更

- 自信: 候補者
- 次の場合はスキップしてください: PR の説明、スクリーンショット、デザイン レビュー、または近くのコードで視覚的な変更が明示されており、Bugbot のコメントでは共有の視覚的なデフォルトが変更されたことのみが再度述べられています。
- 次の場合はスキップしないでください: コメントがアクセシビリティ、フォーカスの可視性、キーボード ナビゲーション、色のコントラスト、または PR が意図的に変更していないコンポーネント API コントラクトを指している場合。
- 信号の例: 所有者が「意図的」または「意図的」と応答する、フォーカスのアウトライン、ボタンのサイズ、間隔、または共有コンポーネントのビジュアルデフォルトに関するコメント。

<a id="upstack-or-stack-local-usage-bugbot-cannot-see"></a>

### アップスタックまたはスタックローカルの使用状況をバグボットが認識できない

- 自信: 候補者
- 次の場合はスキップします: Bugbot がエクスポート、コンポーネント、ヘルパー、またはファイルに未使用のフラグを立て、アクティブな Forge の PR リストと差分、上位スタックの差分、または PR コンテキストで、スタック内の後の PR によって使用されていることを示します。
- 次の場合はスキップしないでください: 現在の PR がスタックの一部ではない、シンボルがパブリック API である、または想定されるアップスタックの使用を検証できない。
- 信号の例: 「エクスポートされたコンポーネントは決して使用されません」と「使用されたアップスタック」のような人間による応答。

<a id="temporary-duplication-during-parallel-implementation"></a>

### 並列実装時の一時的な重複

- 自信: 候補者
- 次の場合にスキップします: PR は、削除、置換、または証明される古いパスと並行して新しいパスを維持するために、少量のコードを意図的に複製します。
- 次の場合はスキップしないでください: 重複したコードにより、セキュリティ、課金、データ アクセス、API の動作が変更されるか、または長期間存続する共有抽象化により、明らかにリスクが軽減されます。
- 信号の例: 「重大な重複」または「重複した検証ロジック」。所有者が古いパスが削除されるか、重複ロジックが意図的にローカルであると説明します。

<a id="existing-framework-or-component-invariant-covers-the-warning"></a>

### 既存のフレームワークまたはコンポーネントの不変条件が警告をカバーします

- 自信: 候補者
- 次の場合はスキップしてください: 懸念事項は、共有コンポーネント、フレームワーク コントラクト、型不変、または現在の diff または近くのコードに表示される唯一の信頼できる情報源によってすでに保証されています。
- 次の場合はスキップしないでください: 不変条件が想定されているが強制されていない場合、タイミングに依存している場合、または値が分岐する可能性がある非同期/状態の境界を越えている場合。
- 信号の例: 共有ポップオーバーがビューポート境界を強制する場合、またはローカルでチェックされた値と渡された値が同じソースを共有する null 許容値を強制する場合に、内部ポップオーバーで max-height が欠落していることに関するコメント。

<a id="owner-declared-follow-up-or-deferred-cleanup"></a>

### 所有者が宣言したフォローアップまたは延期されたクリーンアップ

- 自信: 候補者
- 次の場合はスキップしてください: PR 所有者が、この問題は既知の続報であり、現在の PR によって動作が悪化しておらず、コメントが高リスク領域に関するものではないと明示しています。
- 次の場合はスキップしないでください: エージェントが所有者の入力なしで動作している、問題が中/高重大度の製品動作である、または延期すると新しい回帰がマージされる可能性があります。
- シグナルの例: 「それについては後で考えます」または「最終的には削除します」。

<a id="self-withdrawn-or-explicit-false-positive-rule-comments"></a>

### 自己撤回または明示的な誤検知ルールのコメント

- 信頼度: 繰り返し発生
- 次の場合はスキップします: コメント本文またはその後の Bugbot の返信で、調査結果が撤回、準拠、または誤検知であることが明示されており、エージェントは関連するルールをローカルで検証できます。
- 次の場合はスキップしないでください: 唯一の証拠は、人間が高リスクの問題について説明なしに「偽陽性」と言ったことです。
- 信号の例: ファイルがすでに準拠していることを本文で示すファイル命名規則のコメント。

<a id="ask-by-default"></a>

## デフォルトで尋ねる

以前の PR が同様のものを却下した場合でも、これらのカテゴリを自動スキップしないでください。

- セキュリティ、プライバシー、認証、請求、データ保持、トレーニング データ、および許可境界の調査結果。
- 重大度の高い所見。
- 移行、スキーマ、冪等性、同時実行性、およびシステム間の動作に関する調査結果。
- 提案された修正が小規模であり、製品の意図を変えることなく明らかにリスクを軽減するコメント。

過去のデータによると、人間はセキュリティ/データフローのコメントを無視することがあります。これらはチーム全体のスキップ ルールではなく、オーナーの判断の呼び出しとして扱います。

<a id="candidate-learnings-from-recent-babysits"></a>

## 最近のベビーシッターから候補者が学んだこと

新しい候補者がチームに役立つと思われるがまだ成熟していない場合、ベビーシッター中またはベビーシッター後にここに学習内容を追加します。複数の PR がパターンを確認したら、繰り返しの候補者を上記のセクションに昇格させることを好みます。

<a id="manual-reimplementations-of-native-browser-behavior"></a>

### ネイティブ ブラウザーの動作の手動再実装

- 自信: 候補者
- スキップする場合: 実質的にはスキップしません。 diff がネイティブのブラウザの動作を手動の同等の動作に置き換える場合 (ネイティブ スティッキー → JS 配置クローン、ネイティブ スクロール ターゲティング → 転送されたホイール/タッチ イベント、ペイント オーダー オクルージョン → マスク/クリップパス)、そのコードに対する Bugbot のロジック バグの発見は一貫して正当なものです。
- 次の場合はスキップしないでください: この調査結果は、イベント転送のギャップ (ホイール デルタモード、タッチ パン、エッジでのスクロール チェーン、タップ スロップ)、マスク/クリップのヒット テストの発散、またはそのようなコードでのオブザーバーと React の状態のタイミング競合に関係します。デフォルトでは修正されます。
- 信号の例: 「マスクはヒット テストに影響しません」、「オーバーレイはホイール スクロールをブロックします」、「deltaMode を無視します」、「React が状態を適用する前に IntersectionObserver コールバックで実行されます」。
- 出典: 1 件のスティッキー オクルージョン PR: 6 件の Bugbot パス、およそ 18 件の調査結果、すべてが無視されるのではなく修正されました。

<a id="stale-security-review-finding-already-fixed-later-in-the-same-pr"></a>

### 古いセキュリティ レビューの発見は同じ PR で後で修正済み

- 自信: 候補者
- 次の場合はスキップしてください: エージェントのセキュリティ レビュー (または同様のもの) で認証/検証呼び出しの欠落が主張されており、現在の PR ヒントにその正確なゲート (テスト付き) が明確に含まれており、通常はレビューの実行後の後の強化コミットで追加されます。
- 次の場合はスキップしないでください: 引用されたヘルパーが議論中のプリンシパルに対して no-op である場合、それが保護する副作用の後にチェックが実行される場合、または要求されたプリンシパルのカバレッジが欠落している場合。
- 信号の例: ヒントの副作用の前に正確なガードがすでに呼び出されているときに、高い「認証チェックが欠落している」という結果が検出されました。
- ソース: 1 つの Webhook エンドポイント PR の強化コミットがレビューの実行より後になっています。

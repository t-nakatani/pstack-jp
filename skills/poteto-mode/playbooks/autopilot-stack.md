### オートパイロット スタック

**あなたはスタックを所有しますが、着地を所有することはありません。完全な自律性を備えたキューを構築して検証し、オペレータに 1 つの線形ベース ブランチ スタックを渡して確認して着陸させます。****Autopilot-full** の兄弟です。

1. **オーナー ループを変更せずに実行します。** プログラムの forge を 1 回解決します。 GitHub CLI (`gh`) がデフォルトです。 `command -v origin` が成功し、Origin がリポジトリを解決できる場合は、PR の作成、編集、表示、監視、マージ操作に `origin pr ...` を使用します。それ以外の場合は、`gh` に留まり、フォールバックを記録します。決してグラファイトを必要としないでください (`gt`)。 PR ごとに 1 つの Cursor クラウド エージェントがその変更をエンドツーエンドで所有します: ビルド、最初のプッシュ、セルフプルーフの前に開かれる準備ができた PR、セルフプルーフ (ゲート、CI、レシート)、`../references/bugbot-triage.md` ごとの懐疑的なバグボットのトリアージ、スロップストリップ (`cursor-team-kit` プラグイン (`/deslop`) の `deslop` スキル)、 `/no-comments` (**no-comments** スキル)、`playbooks/babysit.md` に従ってグリーンのベビーシッターを行います。作業が自己完結型である場合、所有者は並列化します。約 15 分以内に、すべての所有者が **show-me-your-work** スキルに従って `decisions.tsv` トレイルを開始し、最初のブランチ スナップショットをプッシュし、準備完了の PR を開きます (ドラフトは行われません)。その後、所有者は検証可能なユニットごとにブランチを再度プッシュします (フックオン、WIP コミットは問題ありません)。証跡をコミットしないままにして、レポートに返します。所有者は、自動操縦完全ステップ 2 の `children.tsv` も保持します。
2. **実際のループで監査します。** ルートは 1 時間ごとに監査ティックを実行します。オペレーターの外出中、オートパイロットのフル ステップ 6 に従って、ルートはこのティックを実行するプロンプトを `/loop 1h` に設定します。メモリや損失のある完了通知にリズムを任せないでください。各ティックで、`git show origin/main:pstack/skills/poteto-mode/playbooks/autopilot-stack.md` を使用してこのプレイブックをトランクから再読み込みし、それに対する操作を監査します。そのティック中のドリフトを修正します。一般的な生存確認またはステータス チェックを使用して、各所有者を調査します。副作用のみを進行状況としてカウントします: コミット、プッシュ、PR またはチェック デルタ、および保存レポート。副作用なしに予想される実行時間を経過したレーンをスタックとして扱います。そのままにして、すぐに交換品を送ります。丁寧な返答を待たないでください。すべてのサブエージェントを調査し、自動操縦の完全なステップ 6 に従ってチェックを終了します。
3. **オペレーター ゲートを保持してください。** 宣言してから待ちます。そのため、計画を述べるよう要求することはできません。オペレーターが停止すると、すべての所有者は即座にゼロ書き込み保留を取得します。
4. **各ラウンドを確認します。** 所有者は、リリースされたコードが最終的なものになるとコードレディのヘッド SHA を報告し、ループが緑色の場合は正確なヘッド SHA で STACK-READY を報告します。ルートは、マージレディの代わりに STACK-READY を使用して、オートパイロットフル ステップ 4 に従って各ラウンドを検証します。検証されていないものは何もスタックに入りません。
5. **クリーンな評決に追加し、決してリリースしないでください。** 所有者のマージ、アームの自動マージ、またはクローズはありません。クリーン判定では、検証された順序またはオペレーターが指定した順序で、PR が 1 つの線形ベースブランチ スタックに追加されます。
6. **トポロジでは単一ライター、ビルドでは並列ライター。** 所有者は自分のブランチのみをプッシュし、チップ、現在のベース、および目的の親をレポートします。ルートは唯一のトポロジ ライターです。 PR を追加するには、目的の親をフェッチし、その正確な親チップに子ブランチをリベースし、`ls-remote` チェックの後にのみ `--force-with-lease` でプッシュし、PR ベースを親ブランチに設定します。解決された forge に応じて、`origin pr create --status open --base <parent-branch>` または `gh pr create --base <parent-branch>` で作成します。 `origin pr edit <pr> --base <parent-branch>` または `gh pr edit <pr> --base <parent-branch>` を使用して既存の PR を再ターゲットします。ルート PR のみがトランクを対象とします。 `gt` を通じてチェーンを送信または登録しないでください。
7. **ルートでドリフトを吸収し、何が移動したかを再検証します。** ルートは現在のトランクを取得し、チェーンを下から上にリベースします。リベース サーフェスが所有者のファイル内で競合する場合、その所有者は自身のスライスを修正し、ルートが結果をプッシュします。リベースは、それより上のすべての SHA を書き換え、古い SHA での判定を無効にします。各判定 SHA で `playbooks/shipping.md` のパッチ ID ルールを適用します。有効でなくなったものは、配信前にこのプレイブックのステップ 4 に戻されます。パッチ ID が変更されていない場合でも、プッシュを書き換えるたびにマージアビリティと CI を再実行します。副署名ルールは Autopilot-full から変更されていません。真に新しいピンは、根の新しい副標識の停止を引き起こします。着陸値のドリフトを吸収することは上昇ではありません。
8. **チェーンの配信。** 成果物は検証済み PR の 1 つの線形チェーンであり、解決されたフォージでボトムアップでレビュー可能であり、すべてのリンクが PR 本文またはコメントで検証者の判定を伝えます。オペレーターは、自分でクリックするか、マージ・ホエン・レディを準備することによって、それを確認して着陸します。

**自動操縦の選択。** PR が独立しており、着陸権限が付与されている場合は自動操縦がフルになります。オペレーターが着陸前に確認したい場合、作業が順序付けまたは結合されている場合、またはマージ権限が保留されている場合の自動操縦スタック。

**返信:** スタック ルートとスタック チップへのリンク、リンクごとの 1 行の判定概要、およびその理由とともに保留または除外されたもの。

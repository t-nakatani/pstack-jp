# 共有状態を直列化する前に分離する

同時アクターが可変状態を共有する可能性がある場合、最初に同じ可変オブジェクトが必要かどうかを尋ねます。そうでない場合は、共有を削除します。共有が実際に行われる場合は、ロックファイル、順次フェーズ、排他的所有権など、構造的にシリアル化を強制します。命令と規約は同時実行性の制御ではありません。

**理由:** 共有状態への同時書き込みにより、断続的で再現が難しく、デバッグに費用がかかる競合状態が発生します。

**パターン:**
1. **共有の可変状態を特定します** (ファイルは読み取りと書き込みの両方、ブランチは両方ともプッシュ先、API は定義と使用の両方)。
2. **デフォルト: 共有書き込みターゲットを削除します。** 質問: これらのアクターには 1 つの正規オブジェクトが必要ですか、それとも独立した事実を公開していますか?各アクターに独自のファイル、キー、ブランチ、または状態ディレクトリを与え、読み取り/レポート境界でのみマージします。 2 人のワーカーが独自の `lastX` フィールドを 1 つの `state.json` に書き込む場合でも、共有ミューテーションです。 `indexer-state.json` + `metrics-state.json` はそうではありません。
3. **1 つの共有書き込みターゲットが実数不変である場合のみ、アクセスを構造的にシリアル化します** (ロックファイル、順次フェーズ、シングルライター アクター、またはアトミック コンペア アンド スワップ)。 「ロックが必要です」は、デフォルトの答えとしてではなく、チェックすべきデザインの匂いとして扱います。

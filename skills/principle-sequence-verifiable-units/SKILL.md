# 検証できる単位に分けて順に進める

注文は一連の小さな単位として処理され、それぞれが確認できる状態で終了し、現在の単位が緑色になるまで先に進めません。

**理由:** 原因となったユニットでの破損は、ローカライズするのが簡単です。バッチが埋められた後に破損が検出され、壊れたベースの上にすでにさらに構築されています。それらの同じユニットをシーケンスして、レビュー担当者が再生できる配信にすると、「信じてください」が「赤になってから青になるのを見てください」に変わります。

**実行。** スイープ、移行、または同様の編集を実行する場合は、次の変更を開始する前に各変更を確認してください。各ユニットは前/後のブラケットです。正常な状態、1 つの変更、チェックを実行してから続行します。最初にクリーンなトランクにリベースして、すべてのチェックが実際のベースラインに対して行われるようにします。レバーが編集を行う場合、ユニットごとのチェックはほぼ無料で行われます。とにかく実行してください。

**配信。** 作業を証明する順序でコミットと PR をスタックします。標準的な形状は、最初に失敗したテストがあり、次にその上に修正が加えられます。その他のストーリーの順序としては、再形成前の減算、処理前のベースライン キャプチャ、フィーチャの前の足場などがあります。各コミットは独自に実行され、シーケンスは引数として読み取られます。

各チェックを本物に保つ **prove-it-works** 原則スキルと、ユニットあたりのチェックを安くする **build-the-lever** 原則スキルを補完する順序付け。

<a id="swarm"></a>

# 群れ

N 個の並列クラウド ワーカーをファンアウトします。別々のスライスをカバーすることも、同じブリーフをレースすることも、両方を混合することもできます。親は待機して集計し、1 つのレポートを返します。

<a id="start"></a>

## スタート

何かを起動する前に、フェーズごとに 1 つのエントリを含む todolist を開きます。

1. フレーム
2. ファンアウト
3. 集合体
4. レポート

<a id="phase-a-frame"></a>

## フェーズ A: フレーム

1. 完了述語と、swarm が返さなければならないアーティファクトまたはレポートを記述します。
2. 形状をお選びください。スライスに分割したり、同じブリーフで N 人の労働者を競い合ったり、両方を混ぜたりできます。種族または混合シェイプの場合は、スポーン前に `first pass`、`rank all`、または `best-of` を宣言します。
3. N をユーザーから設定するか、形状から導出します。 N はワーカーの合計であり、クラウドの同時実行制限ではありません。
4. `~/.cursor/rules/pstack-models.mdc` の `swarm workers` 行からワーカー モデルを選択します。ルールまたはその行が欠落している場合は、`grok-4.7-xhigh-fast` を使用してください。 `auto` または `inherit-parent` の場合は、ワーカーが親モデルで実行されるように、`model` を省略します。タスク ツールがスラッグを拒否した場合は、デフォルトを使用してその旨を伝えます。デフォルトが拒否される場合は、エラー メッセージにある同じファミリーの最も近い有効なスラッグを使用します。モデル レースの場合は、各アームのモデルに最初に名前を付けます。
5. 書き込み時に各ワーカーに独自の書き込み可能な出力を与えます。ワーカーがコミットを検証または測定するとき、各ブリーフは正確な SHA に名前を付けます。測定概要には、方法 (サンプル数、1 つのサンプルとは何か、順序) の名前も記載されています。ワーカーは両方を結果に記録します。

<a id="phase-b-fan-out"></a>

## フェーズ B: ファンアウト

`subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`、およびステップ 4 モデル (`auto` または `inherit-parent` は未設定のまま) を使用して、1 つのメッセージで N 個のワーカーすべてを生成します。 `environment: "local"` は、作業者がユーザーのコンピュータ上の何かにアクセスする必要がある場合にのみ使用してください。

ワーカーがデフォルト以外のプッシュされたブランチから開始する必要がある場合は、`cloud_base_branch` を渡します。

すべてのブリーフは独立しています。目標、範囲、正確なスライスまたはレースアーム、検証方法、報告内容を含めます。レポートでは、証拠とともに `PASS`、`ISSUES`、または `BLOCKED` を使用します。欠陥を証明できる作業者は `ISSUES` を報告し、最初の問題だけでなく、証明できるすべての問題をリストします。

従業員が脱落した場合は、N-1 に進み、それをメモします。

<a id="phase-c-aggregate"></a>

## フェーズ C: 集合体

端末の結果を読み取ります。 SHA とメソッドの簡単な名前が記録されていない結果を削除し、そのワーカーを 1 回再生成します。 2 回目のミスの後、ギャップを記録します。ギャップはパスとしてカウントされません。カバレッジのためには、必要なすべてのスライスに結果が必要です。レースの場合は、事前に宣言された選択ルールが適用されます。最初のパス、すべてのランク、またはベストオブを使用します。生のワーカーダンプを貼り付けないでください。

コンパクトな結果テーブル、1 行の証拠のある問題、および明示的なギャップまたは欠落を保持します。

<a id="phase-d-report"></a>

## フェーズ D: レポート

テーブルを含む 1 つの統合チャット レポートを返し、ワンライナー、ギャップまたはドロップアウト、および使用時のレース ルールを発行します。

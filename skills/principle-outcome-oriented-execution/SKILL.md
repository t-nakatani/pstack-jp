# 検証できる最終状態を目指す

滑らかな中間状態を保持するのではなく、意図した検証可能な最終状態に合わせて最適化します。

**理由:** すべての中間ステップを完全に安定した状態に保つと、多くの場合、長期にわたる負債となる一時的な互換性コードが作成されます。ターゲット アーキテクチャに収束し、明示的な検証境界で正しさを証明します。

**コアルール:**
- 過渡的な安定性よりも最終状態の整合性を優先します
- 中間の破損は、計画され、範囲が定められ、元に戻せる場合には許容されます。

**ガードレール:**
- 明示的なフェーズ境界を使用した計画的な書き換えと移行にこれを使用します。
- 一時的な破損が許容される場所を宣言します
- 移行中にアクティブにタッチされた領域の高信号チェックを継続します
- 計画完了時に完全な静的検証と実行時検証が必要

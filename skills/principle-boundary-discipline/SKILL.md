# 境界で検証する

検証、型の絞り込み、エラー処理をシステムの境界に置きます。内部コードは無条件に信頼します。業務ロジックを純粋関数に置き、その周囲の入出力処理は薄く機械的に保ちます。

**理由：** あちこちに散らばった検証は雑音と重複を生み、安全性を過信させます。フレームワークとの接続処理からロジックを切り離し、フレームワークなしでテストできるようにします。

**パターン:**
- **境界で**（CLI引数、設定ファイル、外部API、ネットワークプロトコル）：検証し、エラーを返し、防御的に扱います。
- **システム内部で：** 型付きデータを扱い、エラーを伝播し、再検証しません。型を信頼します。
- **境界を越えて：** 境界の内部表現ではなく、ドメインの概念を公開します。汎用の仕組みは内部に、用途固有の方針は周辺に置きます。

**アプリケーション:**

検証とエラー処理:
- 設定は業務ロジックの中ではなく、解析時、つまり境界で検証します。
- 境界で、生データをドメインの型に変換します。
- 通信、ストレージ、フレームワーク、転送形式の型を、公開APIから再エクスポートしません。
- 境界で検証済みなら、呼び出しの奥で重複したnilチェックをしません。

コード構成:
- 業務ロジックは、フレームワークに依存しない純粋関数にします。
- 解析関数は、生のバイト列から型付き状態への純粋な変換にします。
- プロンプトの構築は、構造化された状態を入力し、文字列を出力します。
- 採点と評価は、状態から結果への純粋な変換にします。

**テスト:**
- 「このデータは、今システムの境界を越えているか」。越えていなければ、検証は冗長です。
- 「周囲の処理が呼び出すだけの純粋関数にできるか」。できるなら抽出します。

# 測定値の意味を説明する

測定された数値はシステムに関する主張です。それを信頼したり、報告したり、それに基づいて行動したりする前に、何がそれを制限しているのかを見つけて、それが何か他のものを測定したことを除外してください。

**理由:** 失敗した実行でも、妥当な数値が出力されます。失敗したリクエスト、作業をスキップしたキャッシュ、実行されなかったコード、デフォルト設定のままのサイド、および実行間のノイズはすべて、正常に見える結果を生成します。数値が 2 倍にならない理由を説明できない場合は、何を測定したのかがわかりません。

**パターン:**

- **「なぜ 2 倍にしないのか?」と尋ねる** コア、ロック、ディスク、ネットワーク、ロード ジェネレーター自体など、結果を制限するリソースまたはコード パスに名前を付けます。プロファイルまたは実行中に取得されたシステム カウンターから取得し、ソースにマップします。コードを読んで推測することは制限ではありません。
- **この数値が他に測定できるものをリストし、証拠とともにそれぞれを除外します。** 通常疑わしいのは、エラー、スキップまたはキャッシュされた作業、調整されていない側、ノイズ、および端から端まで問題にするには小さすぎる部分です。
- **証拠を番号とともに保管してください。** 読者が主張を確認できるように、ラン カウント、スプレッド、およびリミッターをメモまたはリンクされた成果物に記載します。

パフォーマンス数値を取得するには、[benchmark-checklist](../benchmark-checklist/SKILL.md) スキルを使用して完全な手順を実行します。評価結果については、トライアルについて同じことを尋ねます。すべての実行でタスクが実行されたか、トライアルとモデル間でギャップが維持されているか、シナリオが重要かどうかです。

数値の背後にある証拠にラン カウント、スプレッド、名前付きリミッターがない場合、または変更された部分にかかった時間よりも節約された時間が長い場合は、これをスキップしました。

出力が本物であることをチェックする [Prove It Works](../principle-prove-it-works/SKILL.md) とは異なります。これにより、測定された数値がユーザーの言う通りの意味であるかどうかがチェックされます。

# benny 自動化インテント

<a id="what-i-want-to-automate"></a>

## 自動化したいもの

1 つのスラック問題チャネルで連携して動作する 2 つのCursor オートメーションが必要です。

<a id="automation-1-triage-issue-reports"></a>

### 自動化 1: 問題レポートのトリアージ

- トリガー: 誰かが構成済みのソース スラック チャネルに新しいトップレベル レポートを投稿すると、そのレポートでこの自動化が開始され、元のスレッド座標が維持されるようにしたいと考えています。
- の動作: スレッドと添付ファイルを読み取り、レポートをバグまたはパフォーマンスの問題、機能リクエスト、質問、フィードバック、または再ルーティングとして分類し、ルーティングする前に所有している可能性のあるレイヤーをトレースする必要があります。
- トラッカー: 設定したトラッカーで重複を検索し、信頼できる重複を更新し、明らかなまったく新しいバグに対してのみチケットを作成するようにしたいと考えています。
- ツール: スラック スレッドの読み取りおよび応答アクセス、構成されたトラッカー統合、およびオプションのルーティング マップが必要です。
- 結果: ソース スレッドに短い判定と `[benny:bug]`、`[benny:performance]`、または `[benny:other]` を含む返信が 1 つだけ必要です。バグまたはパフォーマンス マーカーにはトラッカー URL が含まれる場合があります。
- 境界: このオートメーションがソース チャネルにルート メッセージを投稿することは望ましくありません。

<a id="automation-2-reproduce-and-fix-confirmed-bugs"></a>

### 自動化 2: 確認されたバグの再現と修正

- トリガー: この自動化を同じ新しいトップレベル レポート、またはセットアップ中に選択した別のサポートされているトリガーから開始し、元のスレッドで信頼できるトリアージ マーカーを待ちます。
- ゲート: 誰かが明らかに修正を所有している場合は停止してほしいです。既存のプルリクエストまたはマージされたコミットによってレポートが修正される可能性がある場合は、競合する変更ではなく検証が必要です。
- の動作: 設定した制御アダプターと機能マップを使用し、実際の UI で正確な症状を 2 回再現し、スクリーンショット、ビデオ、読み取り専用状態のクロスチェックをキャプチャしたいと考えています。
- 修正: 既存のプル リクエストをオーサリングせずに検証できるようにしたいです。再現が確認された後は、1 つの限定された根本原因の修正を試み、テストが安価な場合は tdd を使用し、爆発範囲をスモークし、前後の証明に合格した場合にのみドラフト プル リクエストをオープンする可能性があります。
- ツール: スラック スレッドの読み取りと返信のアクセス、リポジトリと履歴のアクセス、ドラフト プル リクエストの作成、構成されたトラッカー、およびコントロール アダプターが必要です。
- 結果: ソースまたはオプションの操作スレッドでの証拠と検証された結果、およびオプションのドラフト プル リクエストが必要です。更新は簡潔にする必要があります。
- 境界: このオートメーションがソース チャネルにルート メッセージを投稿することは望ましくありません。

<a id="shared-rules"></a>

### 共有ルール

- ソースチャネルとルートスレッドの座標を実行全体にわたって不変のままにしたいと考えています。
- 私は、委任や所有権の修正ではなく、ユーティリティとデバッグボットを証拠として扱います。
- サブエージェントによる支援を許可していますが、Slack に投稿したり、Slack 認証情報を受信したりすることはできません。
- このパック全体をターゲット リポジトリの `.cursor/automations/benny/` でコミットしたいと考えています。その `SKILL.md` ファイルは直接の自動化命令であり、登録されたプラグイン スキルではありません。
- `how`、`why`、`tdd`、`unslop`、および必要な原則スキルなどの共有依存関係に対してのみ、ターゲット リポジトリのコミットされた `.cursor/settings.json` を通じて pstack を有効にしたいと考えています。
- 各ライブ オートメーション プロンプトで、コミットされた操作ファイルを直接読み取るようにしたいと考えています。プラグインのキャッシュ パス、コピーされた抜粋、またはスラッシュ スキルの検出は望ましくありません。
- ユーザー所有の構成、機能マップ、ルーティング マップ、およびシークレットを `.cursor/automations/benny/` の外に保持しているため、パックの更新で上書きできません。
- チャネル座標、トラッカーアクセス、制御アダプター、または機能マップが見つからないか不確実な場合、両方のオートメーションをフェールクローズしたいと考えています。
- ドラフトのプルリクエストのみが必要です。マージやデプロイは行わないでください。

## 

人間は、このファイルにCursorを合わせてセットアップを開始します。発見されたベニースラッシュスキルを探したり発動したりしないでください。

1. どのリポジトリがオートメーションを実行するかを尋ねます。
2. は、この `FOR_AGENTS.md` を含むディレクトリをソース パックとして扱います。
3. ソース パック全体を `<target-repository>/.cursor/automations/benny/` にマージします。
4. は、すべての宛先専用ファイルを保存します。無関係なファイルを削除したり、ユーザー所有の設定、機能マップ、またはルーティング マップを上書きしたりしないでください。
5. ソース管理パスにある既存の宛先ファイルが異なる場合、ローカル編集を破棄せずに差分を確認してマージします。所有権があいまいな場合は、交換する前に立ち止まって尋ねてください。
6. コピーされた `FOR_AGENTS.md` と `skills/setup-benny/SKILL.md` がターゲット リポジトリに存在することを確認します。
7. は、ターゲット リポジトリから直接 `.cursor/automations/benny/skills/setup-benny/SKILL.md` を読み取り、追跡します。

このエントリをターゲット リポジトリの `.cursor/settings.json` にマージしてほしいです。

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

は、無関係な設定とプラグインをすべて保持します。既存のファイルで jsonc が使用されている場合、コメントと有効な jsonc 構文を保持します。

ターゲット リポジトリにルートされている新しいエージェントからの検証が必要です。 pstack の `how`、`why`、`tdd`、`unslop`、および benny によって使用される主要なスキルがプロジェクト スコープ内で解決されていることを確認します。現在のセッションまたはユーザー対象のインストールからロードされたスキルはカウントされません。

プロジェクト スコープのプラグインが利用できない場合、または共有依存関係が解決されない場合は、停止して何が失敗したかを説明します。 `.cursor/automations/benny/skills/` をプラグイン マニフェストに追加したり、そのファイルがスラッシュ スキル リストに表示されることを期待したりしないでください。

# 自動トリアージ プロンプト

> コピーされたセットアップ ワークフローのソース マテリアル。コピーされたパックがオートメーションが実行されるリポジトリにコミットされたことを `automate` が確認した後、このインテントを組み込みの `automate` ドラフトに言い換えます。

この実行については `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読んでフォローしてください。

構成ソース。このリポジトリ相対パスは、同じターゲット リポジトリでコミットされる場合にのみ含めます。それ以外の場合は、構成された値を言い換えます。プラグイン ソースまたはキャッシュ パスは決して使用しないでください。

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成インテントでは、これを構成されたソース Slack チャネルの新しいトップレベル レポートとして説明する必要があります。

ソース チャネルとルート スレッドのタイムスタンプを不変として扱います。いずれかが欠落しているか、構成と一致しない場合は、問題トラッカーへの投稿や書き込みを行わずに停止します。

コミットされた運用ファイルには、分類、添付ファイルのレビュー、原因追跡、ルーティング、重複排除、トラッカー書き込み、および最終判定が含まれます。進捗メッセージを投稿しません。ルート メッセージをソース チャネルに投稿しないでください。

コーディネーターは唯一の Slack ポスターです。委任されたワーカーは読み取り専用であり、結果のみを返す必要があり、すべての Slack 書き込みアクションに対して明示的な禁止を受ける必要があります。

構成されたマーカーを 1 つだけ使用して単一の判定を終了します。

```text
[benny:bug]
[benny:performance]
[benny:other]
```

バグまたはパフォーマンス マーカーにより `tracker=<URL>` が追加される場合があります。

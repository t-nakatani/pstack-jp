# 自動化プロンプトを再現します

> コピーされたセットアップ ワークフローのソース マテリアル。コピーされたパックがオートメーションが実行されるリポジトリにコミットされたことを `automate` が確認した後、このインテントを組み込みの `automate` ドラフトに言い換えます。

この実行については `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読んでフォローしてください。

構成ソース。このリポジトリ相対パスは、同じターゲット リポジトリでコミットされる場合にのみ含めます。それ以外の場合は、構成された値を言い換えます。プラグイン ソースまたはキャッシュ パスは決して使用しないでください。

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成インテントでは、これを構成されたソース Slack チャネルの新しいトップレベル レポートとして説明する必要があります。これには、構成済みのリポジトリ、デフォルトのブランチ、問題トラッカー、コントロール アダプター、機能マップ、およびドラフト プル リクエスト機能が含まれている必要があります。

ソース チャネルとルート スレッドのタイムスタンプを不変として扱います。いずれかが欠落している場合、または構成と一致しない場合は、投稿せずに停止します。

このスレッド内で構成済みの優先順位付け ID から構成済みの優先順位付けマーカーが送信されるのを待ちます。 `[benny:bug]` または `[benny:performance]` についてのみ続行してください。

再現を試みる前に、構成されたコントロール アダプター スキルが必要です。実際の UI を通じて、正確な特徴的な症状を 2 回再現します。既存のプル リクエストまたはコミットを、オーサリングせずに検証します。再現が確認され、操作可能なファイルの修正ゲートが確立された後でのみ、制限付き修正を試みてください。

コーディネーターは唯一の Slack ポスターです。すべての子プロンプトは、`SendSlackMessage`、`PostToSlack`、`chat.postMessage`、およびその他すべての Slack 書き込みを禁止する必要があります。子どもたちは所見のみを返します。

ソース チャネルにルート メッセージを投稿しないでください。

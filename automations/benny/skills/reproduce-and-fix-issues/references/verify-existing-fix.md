<a id="verify-an-existing-fix"></a>

# 既存の修正を確認する

オープンなプル リクエストまたはマージされたコミットによってレポートが修正される可能性がある場合は、このモードを使用します。

既存のアーティファクトが修正を所有しています。確認してください。編集したり、競合するパッチを作成したり、別のプル リクエストを開いたりしないでください。

<a id="qualify-the-artifact"></a>

## アーティファクトを修飾する

1 つの具体的なアーティファクトが必要です。

- 症状に対処するコード変更を含むオープン プル リクエスト
- マージされたプル リクエスト
- コードとインテントが一致するマージされたコミット

プル リクエストやコミットのないスレッドのクレーム、トラッカー ステータス、ブランチ名、または原因の仮説だけでは十分ではありません。

複数のアーティファクトが存在する場合は、ソース スレッドまたはトラッカーからリンクされているものを選択します。それ以外の場合は、影響を受けるコードに最も近いものを選択し、その理由を述べてください。

<a id="protect-the-working-tree"></a>

## 作業ツリーを保護する

リポジトリがサポートしている場合は、分離されたワークツリーまたは別のクリーンなチェックアウトを使用します。ユーザーによる変更を上書きしないでください。

レコード:

- ベースライン リビジョン
- パッチ適用済みリビジョン
- プル リクエストまたはコミット URL
- 両方の実行で共有されるビルドと環境の入力

通常の `github.com` プル リクエスト リンクを使用します。

<a id="measure-the-baseline"></a>

## ベースラインを測定する

オープンなプル リクエストの場合は、そのベース ブランチをベースラインとして使用します。

マージされた修正の場合、そのリビジョンがビルドされて古い動作を表す場合は、修正の直前のリビジョンを使用します。

設定された制御アダプターを通じて:

1. ベースライン アプリを起動します。
2. 正しいアプリと環境を確認してください。
3. 実際の UI アクションを通じて、報告されたパスを実行します。
4. 特徴的な症状を観察してください。
5. リセットして繰り返します。
6. ベースライン記録、スクリーンショット、および状態チェックをキャプチャします。

ベースラインで症状が 2 回現れない場合、ベースラインはありません。修正が機能すると主張しないでください。

<a id="measure-the-patched-build"></a>

## パッチ適用されたビルドを測定する

同じ環境とデータを使用してプル リクエストをビルドして実行するか、コミットを修正します。

1. 同じ UI パスを実行します。
2. これを 2 回繰り返します。
3. 壊れた状態が解消されたことを確認します。
4. 期待した状態が表示されることを確認します。
5. 録画後のキャプチャ、スクリーンショット、および同様の状態の確認。

コンパイルやテストで停止しないでください。 After 結果は、実行中のパッチ適用済みアプリから取得される必要があります。

<a id="outcomes"></a>

## の結果

<a id="confirmed"></a>

### 確認済み

ベースラインは 2 回再現され、パッチ適用されたビルドでは 2 回解決されます。

- 操作ステータスを検証済みとしてマークします。
- アーティファクトをリンクします。
- ソース プリフライトの後に、簡潔なソース スレッド応答を 1 つ投稿します。
- 前後の結果を含めます。
- プル リクエストをオープンしていません。

<a id="insufficient-fix"></a>

### 修正が不十分です

この症状は、ベースライン ビルドとパッチ適用済みビルドの両方で発生します。

- 操作ステータスを再現したが修正されていないとマークします。
- アーティファクトをリンクし、症状が解決しなかったことを伝えます。
- 実行でまだ使用されていない場合は、通常の確認済み再現ソース更新を投稿します。
- 競合するプル リクエストをオープンしません。

<a id="inconclusive"></a>

### 結論が出ない

ベースラインが再現されない、パッチ適用されたアプリが実行できない、または識別可能な状態を示す証拠がありません。

- 成功を主張しないでください。
- 半分が測定できなかった状態。
- 結果を操作スレッドに保持するか、出力を実行します。
- 直接の質問に回答が必要な場合を除き、ソース スレッドには何も投稿しないでください。

<a id="cleanup"></a>

## クリーンアップ

両方のビルドを停止し、保持ポリシーに従って一時プロファイルとキャプチャを削除し、ユーザーの作業を破棄せずにリポジトリを以前の状態に戻します。

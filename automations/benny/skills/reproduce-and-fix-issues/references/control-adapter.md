# コントロールアダプター契約

ベニーは、すべてのアプリの起動方法や操作方法を知りません。ユーザーは、ターゲット アプリに対してこのコントラクトを実装する 1 つのコントロール スキルまたはアダプターを構成する必要があります。

`control.skill_name`にスキル名を設定します。

完成したユーザー向け機能マップのパスを `control.feature_map_path` に設定します。コピーした例を編集する代わりに、`.cursor/automations/benny/` の外側に [`feature-map.example.md`](./feature-map.example.md) をコピーして入力します。

スキル、機能マップ、または必要な機能が存在しないか、曖昧であるか、不完全な場合、再現および修正作業はフェールクローズする必要があります。

<a id="required-capabilities"></a>

## 必要な機能

<a id="bring-up"></a>

### 起動

要求されたアプリ リビジョンを要求されたテスト環境で開始します。

入力:

- リポジトリとリビジョン
- ビルドまたは開始モード
- ワークスペース、アカウント、フィクスチャ、および機能状態の要件
- アーティファクト ディレクトリ
- 完成した機能マップのパス

戻り値:

- セッション識別子
- アダプターが正しいアプリと環境を確認した方法
- 安定したアプリ マーカー
- 後の呼び出しで必要な実行プロセスまたはターゲットの詳細
- 不足している機能

アダプターは、ターゲット アプリを類似のウィンドウ、シェル、または運用インスタンスから区別する必要があります。

<a id="drive-ui"></a>

### ドライブ UI

実際のユーザー アクションを実行します。

- クリック
- タイプ
- キーを押します
- スクロール
- ドラッグ
- サイズ変更
- アプリのコントロールをナビゲートする

ロール、ラベル、安定したセレクターを優先します。新しいスクリーンショットを作成した後にのみ座標を使用してください。

各アクションと観察された状態変化を返します。

症状を引き起こすために、内部状態の設定、非表示のアプリ メソッドの呼び出し、ストレージへの直接書き込み、または DOM 変更の挿入を行わないでください。

<a id="drive-mapped-features-and-states"></a>

### ドライブにマップされた機能と状態

アプリを実行する前に、関連する機能マップのセクションをお読みください。

アダプターは次の方法を公開する必要があります。

- ユーザーに表示されるパスを通じて、マップされたすべてのフィーチャをナビゲートします。
- その機能に対してリストされているアダプター アクション名を呼び出します。
- デフォルト、ホバー、フォーカス表示、アクティブ、無効、読み込み、空、エラー、選択、開いている、展開、および機能固有の状態が適用される場合にそれらの状態と対話します。
- 安全なフィクスチャ データ、権限、フラグ、サービス応答、またはサポートされているテスト コントロールを通じて状態を調整します。
- 2 回目の独立した再現試行のために機能をリセットします。
- スクリーンショット、ビデオ、および機能マップで指定された読み取り専用クロスチェックをキャプチャします。

ロール、アクセス可能な名前、ARIA 関係、安定したコンポーネント マーカー、および目的の名前が付けられたデータ属性を使用します。生成された CSS クラスや StyleX クラス、動的ハッシュ、子インデックス、または脆弱な DOM 位置は決して使用しないでください。

前提条件を調整することは、報告された症状を挿入する許可ではありません。再現自体は、やはり実際のユーザー インタラクションから得られるものでなければなりません。

<a id="inspect-state"></a>

### 状態の検査

状態を読み取り、UI に表示される内容を確認します。

例:

- アクセシビリティ ツリー
- DOM またはビュー階層
- プロセス状態
- ローカルログ
- ネットワークリクエストステータス
- アプリ公開デバッグ状態

インスペクションは読み取り専用です。クエリの状態が変化する場合、それは `drive UI` に属し、実際のユーザー アクションを表す必要があります。

<a id="screenshot"></a>

### スクリーンショット

現在のアプリの状態を要求されたパスにキャプチャします。

戻り値:

- ファイルパス
- キャプチャ時間
- アプリのマーカーまたはウィンドウのタイトル
- 表示されるべきものの簡単な説明

スクリーンショットには、正しいアプリがテスト中であることを証明するのに十分なアプリ クロムが表示されている必要があります。

<a id="recording"></a>

### 録音中

完全な再現パス周辺で画面の記録を開始および停止します。

戻り値:

- ファイルパス
- 開始時間と停止時間
- キャプチャされたウィンドウまたは領域
- オーディオまたは機密性の高いオーバーレイが省略されたかどうか

録画には、セットアップや読み込み画面だけでなく、識別可能な最終状態も表示する必要があります。

<a id="cleanup"></a>

### クリーンアップ

アダプターによって作成されたプロセスとセッションを停止します。

ディスポーザブルを取り外します:

- ブラウザまたはアプリのプロファイル
- 一時ワークスペース
- アダプターが作成したアカウントまたはフィクスチャのテスト
- ポートとトンネルをデバッグする
- 保持期間を超えてキャプチャする

停止、削除、保持、または人のために残されたものを返します。

クリーンアップではユーザーの作業を削除してはなりません。

<a id="adapter-behavior"></a>

## アダプターの動作

アダプターは次のことを行う必要があります。

- 再現が開始される前に機能をレポートします。
- どの機能マップ セクションを駆動でき、どのセクションがブロックされているかを報告します。
- ベースライン ビルドとパッチ適用済みビルドに同じ環境入力を使用します。
- Surface の起動が失敗として失敗します。
- バウンド再試行。
- ログや成果物に秘密を入れないでください。
- キャプチャをリポジトリの外に保管します。
- 2 回の再現試行間のフレッシュまたはリセット状態をサポートします。
- ユーザーが安全なテスト アクションを明示的に構成しない限り、運用環境の変更は避けてください。

<a id="environment-translation"></a>

## 環境翻訳

環境ブロックを宣言する前に、プラットフォーム固有の名詞を使わずに欠陥を再度述べ、利用可能な環境で同じ動作を安全にテストできるかどうかを尋ねます。

例:

- 名前付きブラウザとは、任意の外部ブラウザを意味します。
- 名前付きキーは、構成されたショートカットを意味する場合があります。
- 名前付きリモート ホストは、遅延または切断されたリモート ターゲットを意味する場合があります。

変換された試行は、同じ基礎となる動作をテストする場合にのみ使用してください。翻訳された証拠としてラベルを付けます。欠落している環境が欠陥の一部である場合、それを正確な再現とは呼ばないでください。

ハードウェア プロンプト、オペレーティング システムの許可ダイアログ、デバイス専用 API、および利用できないアカウント状態は、実際のブロックである可能性があります。

<a id="setup-check"></a>

## セットアップのチェック

再現自動化を有効にする前に、無害なアダプター チェックを 1 つ実行します。

1. アプリを起動します。
2. 安定したアプリマーカーを確認します。
3. 完成した機能マップ セクションを 1 つロードします。
4. ユーザー パスを通じてその機能に移動します。
5. マップされたアダプター アクションを通じて 1 つの使い捨て状態を実行します。
6. 結果の状態を検査します。
7. スクリーンショットをキャプチャします。
8. 短いクリップを録画します。
9. クリーンアップします。

9 つの手順がすべて成功し、ソース チャネルの Slack 投稿が関与していない場合にのみ、再現作業を有効にします。

# ベニーのセットアップ

Benny は pstack 内の休止中の自動化パックとしてリリースされます。プラグイン マニフェストは pstack の通常のスキル ルートのみを公開します。このファイルと 2 つの操作ファイルはスラッシュ スキルではありません。

人間は、Cursorをパックの `FOR_AGENTS.md` にポイントしてセットアップを開始します。ブートストラップ フローは、パック全体をターゲット リポジトリにコピーし、`.cursor/automations/benny/skills/setup-benny/SKILL.md` でこのファイルを直接読み取ります。

Benny には外部構成と 2 つのライブ Cursor オートメーションが必要です。

ユーザーが明示的に要求するまで、オートメーションを作成または更新しないでください。プラグイン ファイル、プロンプト、またはコミットされた設定にシークレット値を決して入れないでください。

<a id="1-copy-the-pack-and-enable-shared-pstack-skills"></a>

## 1. パックをコピーし、共有 pstack スキルを有効にします

これは、Benny 構成を要求する前、および組み込みの `/automate` スキルを呼び出す前に実行してください。

どのリポジトリが自動化を実行するかを尋ねます。ソース パックは、`FOR_AGENTS.md` を含むディレクトリです。宛先は `<target-repository>/.cursor/automations/benny/` です。

ソース パック全体を宛先にマージします。

1. 宛先が存在しない場合は作成します。
2. すべてのソース ファイルを同じ相対パスにコピーします。
3. 宛先のみのファイルを保存します。インストールまたは更新中に無関係なファイルを削除しないでください。
4. ユーザー所有の設定、機能マップ、およびルーティング マップを宛先の外部に保持します。決して上書きしないでください。
5. 既存のソース管理ファイルが異なる場合は、ローカル編集を破棄せずに差分を検査してマージします。所有権があいまいな場合は、交換する前に立ち止まって尋ねてください。
6. 宛先に `FOR_AGENTS.md`、このセットアップ ファイル、両方の操作ファイル、それらの参照、およびテンプレートが含まれていることを確認します。

このファイルがターゲット宛先からすでに読み取られている場合は、コピーが完了したものとして扱い、続行する前に同じ検証を実行します。

pstack をターゲット リポジトリの `.cursor/settings.json` に追加します。ファイルまたは `.cursor` ディレクトリが存在しない場合は、作成します。

このエントリを既存の JSON または JSONC にマージします。

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

無関係なすべてのトップレベル設定と他のすべてのプラグイン エントリを保存します。 `plugins.pstack` がすでに存在する場合は、その `enabled` 値のみを変更します。ファイルで JSONC を使用する場合、コメントと有効な JSONC 構文を保持します。ファイルを編集した後に検証します。

ターゲット プロジェクトをリロードするか、そこにルートする新しいエージェントを開始します。これらの共有 pstack スキルがプロジェクト スコープから解決されることを確認します。

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

現在のセッションまたはユーザースコープのプラグインからロードされたスキルはカウントしません。このチェックでは、ターゲット リポジトリ内の新しいエージェントがプロジェクト設定を通じて pstack を受信することが示される必要があります。

プロジェクト スコープのプラグインのインストールが利用できない場合、または共有依存関係が解決されない場合は、停止して失敗について説明します。

Benny ファイルは `.cursor/automations/benny/` から直接読み取られます。そのディレクトリをプラグイン マニフェストに追加したり、その `SKILL.md` ファイルがスラッシュ スキル リストに表示されることを期待したりしないでください。

いずれかの自動化を有効にする前に、`.cursor/settings.json`、`.cursor/automations/benny/`、および参照されたシークレットフリー構成をコミットする必要があることをユーザーに伝えます。ユーザーが要求しない限り、それらをコミットしないでください。

このチェックに合格すると、ライブ オートメーション プロンプトは、コミットされた操作ファイルを安定したリポジトリ相対パスで読み取ることができます。プラグイン キャッシュ パスを埋め込んだり、ファイルの内容をコピーしたりしてはなりません。

<a id="2-adapt-the-configuration"></a>

## 2. 構成を調整する

コピーした例を開きます。

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

ユーザー所有のコピーを `.cursor/automations/benny/` の外に作成します。これらは構成ファイルであり、パック ファイルではありません。場所の例:

- プロジェクト構成 (`.cursor/benny/configuration.yaml` など)
- プロジェクト機能マップ (`.cursor/benny/feature-map.md` など)
- プロジェクト ルーティング マップ (`.cursor/benny/routing.md` など)
- ユーザー構成 (`~/.config/benny/configuration.yaml` など)
- ユーザー機能マップ (`~/.config/benny/feature-map.md` など)

オートメーションで再現される可能性のあるユーザー向け機能ごとに 1 つの機能マップ セクションを入力します。ユーザーの視点に置いてください。マップ内の実装の詳細や現在のコード パスを固定しないでください。

コピーした例は編集しないでください。パックの更新により、競合レビュー後にソース管理ファイルが更新される場合がありますが、ユーザー所有のコピーには決して触れてはなりません。

新しい自動チェックアウトでファイルを読み取る必要がある場合は、ターゲット リポジトリ内のコミットされたシークレットのないファイルを優先します。それ以外の場合は、必要な値をライブ プロンプトに言い換えます。リポジトリ ファイルを参照するのは、自動化が実行されるリポジトリにファイルがコミットされていることを組み込みの `/automate` スキルが確認した後のみにしてください。

コミットされたパックと構成ファイルには、安定したリポジトリ相対パスを使用します。ライブ オートメーションからプラグイン ソース ディレクトリまたはプラグイン キャッシュ パスを参照しないでください。

<a id="3-fill-the-required-choices"></a>

## 3. 必要な選択肢を入力します。

質問または確認:

- ソース Slack チャネル ID
- オプションの操作またはステータス チャネル ID
- リポジトリ URL とデフォルトのブランチ
- トリアージ ID または Slack ユーザー ID
- 問題トラッカーのタイプ、チーム、プロジェクト、ラベル、および取り込みステータス
- トラッカー アダプター スキルまたは MCP アクション
- オプションのルーティング マップ パス
- 必要なコントロールスキル名
- 必須のユーザー向け機能マップ パス
- ステータス絵文字文字列
- プル リクエストの URL 形式
- ポーリングと労力の予算
- トリアージ、再現、コード作業、メディア レビュー用のモデル スラグ

ユーザーのCursor モデル ピッカーまたはサポートされているモデル リストで使用可能として示されているモデル スラグのみを使用します。推測したり、個人的なデフォルトを引き継いだりしないでください。

ソース チャネル、トリアージ ID、リポジトリ、トラッカー アダプター、コントロール スキル、および機能マップは明示的である必要があります。必須の値があいまいなままの場合、セットアップは失敗します。

最終的なオートメーション名、説明、およびプロンプト シムを保存する前に、pstack の `unslop` スキルを使用します。

<a id="4-check-integration-capabilities"></a>

## 4. 統合機能を確認する

トリアージ自動化には次のものが必要です。

- 構成されたソース Slack チャネルとそのスレッドへの読み取りアクセス
- そのチャネルのスレッド応答アクセス
- レポートにメディアが含まれる場合の添付ファイルのメタデータとファイルのダウンロード アクセス
- 構成された問題追跡アダプターを介した検索、読み取り、作成、および更新アクセス

再現自動化には次のものが必要です。

- ソース スレッドへの読み取りアクセス
- ソースチャネルでのスレッド応答アクセス
- 構成された操作チャネルでのオプションの投稿および編集アクセス
- リポジトリの読み取りと履歴へのアクセス
- ドラフト プル リクエストを開くことができるプル リクエスト アクション
- 構成されたコントロール アダプター スキル

読み取りと投稿に対して設定済みの Cursor Slack アクションを優先します。オプションの `BENNY_SLACK_BOT_TOKEN` は、1 つの操作ステータス メッセージの編集や添付ファイルのダウンロードなどの狭いギャップを埋めることができます。値は YAML ではなく、シークレット マネージャーまたは環境に保存します。

文書化されていない統合エンドポイントは使用しないでください。

<a id="5-prepare-the-routing-map"></a>

## 5. ルーティング マップを準備する

ユーザーが再ルートまたは所有者 ping を必要とする場合:

1. `../triage-issue-reports/references/routing.example.md` を `.cursor/automations/benny/` の外にコピーします。
2. すべてのプレースホルダーをパブリックまたは組織ローカルの値に置き換えます。
3. デフォルトでは所有者の ping をオフのままにします。
4. 構成された機能所有者または確認された可能性の高い回帰作成者にのみ ping を許可します。

ルーティング マップが構成されていない場合、トリアージはレポートを分類できますが、宛先や所有者を推測してはなりません。

<a id="6-verify-the-control-adapter"></a>

## 6. 制御アダプターを確認します。

`../reproduce-and-fix-issues/references/control-adapter.md` とユーザーの完成した機能マップを読み取ります。

指定されたスキルが次のことを実行できることを確認します。

- 対象のアプリを起動します
- 実際の UI を通じて、マップされたすべての機能をナビゲートします
- 宣言されたアダプター アクションを通じてマップされた状態を実行する
- 結果を強制せずに状態を検査します
- スクリーンショットをキャプチャする
- 録音の開始と停止
- プロセスと一時データをクリーンアップします

不足している機能がある場合は、再現自動化を無効のままにしてください。実行しなかった複製を主張するのではなく、フェイルクローズする必要があります。

<a id="7-prepare-the-live-automations"></a>

## 7. ライブ オートメーションの準備

これが初めての作成なのか、それとも既存のオートメーションの構成なのかを尋ねます。

いずれかのパスのプライマリ ユーザー意図のソースとして、コピーされたパックから `../../FOR_AGENTS.md` を読み取ります。これを使用して、2 つのトリガー、ツール、指示、結果、共有ルールを理解します。

<a id="first-time-creation"></a>

### 初回作成

オートメーションは一度に 1 つずつ作成します。

各自動化について:

1. コピーされた一致するプロンプト テンプレートを二次内部ソース資料として読み取ります。
2. `FOR_AGENTS.md`、完成した Benny 構成、およびテンプレート インテントを完全な自然言語リクエストに変換します。
3. `.cursor/automations/benny/` の下にある正確にコミットされた操作ファイルを読み取って従うようにライブ プロンプトに指示します。
4. プラグイン ソースやキャッシュ パスではなく、安定したリポジトリ相対パスを使用してください。運用ファイルの内容をライブ プロンプトにコピーしないでください。
5. 組み込みの `automate` スキルを読んで従ってください。
6. `automate` に Slack チャネル、リポジトリ、接続された統合を検出させます。
7. `automate` で、コピーされたパックと参照された構成ファイルが、オートメーションが実行される同じリポジトリにコミットされていることを確認させます。
8. `automate` にそのドラフト表を表示させ、承認を取得し、準備状況を尋ねて、自動化エディターを開きます。
9. 次のオートメーションを開始する前に、このオートメーションのエディターの引き継ぎを終了してください。

`automate` に、構成から入力されたこの完全な優先順位付けの意図を与えます。

- 名前は `benny-triage`。
- 実行ごとに `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読み、従ってください。
- 構成されたソース Slack チャネル内の新しいトップレベル レポートごとにトリガーします。
- トリガーとなったスレッドを読み取り、そのスレッド内でのみ返信します。
- 構成された問題追跡統合を使用します。
- 分類、証拠の検査、原因の追跡、重複排除を行い、明確な新しいバグのみを作成します。
- 構成された `[benny:bug]`、`[benny:performance]`、または `[benny:other]` マーカーとオプションのトラッカー URL を使用して、1 つのスレッドのみの判定を終了します。
- ソース チャネル ルート メッセージを投稿しないでください。

トリアージ エディターの引き継ぎが完了したら、`automate` にこの完全な再現と修正の意図を与えます。

- 名前は `benny-reproduce`。
- 実行ごとに `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読んで従ってください。
- 構成されたソース Slack チャネル内の同じ新しいトップレベル レポートでトリガーします。
- 構成されたリポジトリとデフォルトのブランチを使用します。
- ソーススレッドを読んで、その中でのみ返信してください。
- プル リクエストの作成と、構成されたトラッカー、コントロール アダプター、および機能マップの要件を含めます。 `automate` によって同じリポジトリ内の対象となるコミット済みファイルが確認されない限り、マップされたユーザー パスと状態を言い換えます。
- 行動する前に、信頼できるトリアージ マーカーを待ってください。
- マッピングされた実際の UI を通じて正確な症状を 2 回再現し、証拠をキャプチャします。
- 既存の修正をオーサリングせずに検証します。
- 再現が確認された後にのみオプションの制限付き修正を試み、プルーフとチェックに合格したらドラフト プル リクエストを開きます。
- ソース チャネル ルート メッセージを投稿しないでください。

`automate` の Slack、リポジトリ、統合、完全性、認証、ドラフト レビュー、承認、準備、または編集者への引き継ぎ作業を複製しないでください。

<a id="existing-automations"></a>

### 既存の自動化

組み込みの `automate` スキルは作成専用です。既存のオートメーションの検索、検査、更新には使用しないでください。

構成、ルーティング、制御アダプター、および機能マップの検証を終了します。次に、この簡潔なエディター チェックリストをユーザーに渡します。

既存のトリアージ自動化については、以下を更新します。

- 名前と説明
- `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読み取る直接命令
- 新しいトップレベルの Slack レポート トリガーとソース チャネル
- Slack スレッドの読み取りおよび返信機能
- 問題追跡ツールの統合
- トリアージ指示、スレッドのみのルール、ベニー判定マーカーの言い換え

既存の再現オートメーションの場合は、以下を更新します。

- 名前と説明
- `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読み取る直接命令
- Slack トリガーとソース チャネルのマッチング
- リポジトリとデフォルトのブランチ
- Slack スレッドの読み取りおよび返信機能
- プル リクエスト アクション
- トラッカー、コントロール アダプター、および機能マップの要件
- マーカー待機、証拠、検証、および制限付き修正命令の言い換え

オートメーション エディターで既存の各オートメーションを直接更新するようにユーザーに依頼します。代替品や複製を作成しないでください。

<a id="creation-boundary"></a>

### 作成境界

直接自動化バックエンド サービスまたはバックエンド自動化ツールを決して呼び出さないでください。下書きフィールドを含むブラウザ URL は決して使用しないでください。Cursor プロトコルのディープ リンクを構築したり開いたりしないでください。新しいオートメーションの場合、唯一の終了パスは、組み込みの `automate` スキルのレビュー済みオートメーション エディターのハンドオフです。

エディターの保存後、スレッド セーフティ テストに合格するまでは、どちらの自動化も有効にしないでください。

<a id="8-test-thread-safety"></a>

## 8. スレッドの安全性をテストする

テスト チャネルまたは無害なテスト レポートを使用します。

テストの前に、ターゲット リポジトリの `.cursor/settings.json`、`.cursor/automations/benny/`、および参照されているすべてのシークレットフリー構成ファイルが、自動チェックアウトによって使用されるブランチ上でコミットされていることを確認してください。両方のライブ プロンプトがコミットされた操作ファイルを正確に指していることを確認します。いずれかのチェックが失敗した場合は、停止します。自動化をまだ有効にできないことをユーザーに伝えます。

確認してください:

1. Triage はルート `thread_ts` を保存し、応答として 1 つの判定を正確に投稿します。
2. 判定には、構成されたマーカーが 1 つ含まれています。
3. Repro は、構成された優先順位付け ID からのみマーカーを受け入れます。
4. Repro は、同じ不変のソース座標を保持します。
5. ソース チャネル ルート メッセージが表示されません。
6. 委任されたワーカーは、Slack 書き込みアクションを使用できません。
7. 座標の欠落、親の削除、またはプリフライトの失敗により、ポストもトラッカーの問題も発生しません。

7 つのチェックすべてに合格した場合にのみ、通常のトラフィックを有効にします。
